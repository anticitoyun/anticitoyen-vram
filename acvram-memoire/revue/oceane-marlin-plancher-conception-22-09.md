# Marlin de décodage 94 → 100 % du plancher : où sont les 6 %, et le seul levier au bit qui les vise (22/09, Océane, à sec)

* sources : `verdict-m2-b12-21-09` (D = 42 experts/couche médian, 5,42 Go/pas, Marlin 3,73 ms nsys = 94 % de 3,50 à 1,55 To/s), `verdict-nsys-familles-22-09` (Marlin 3,937 ms à 2 700 : 1,38 To/s = 89 % de 1,55, 77 % du pic 1,79), `verdict-nsys-trtllm-serve` (leur GEMM groupée 3,42 ms sur les mêmes octets : 1,58 To/s), `oceane-ecart-trtllm-2` § 2 (levier 2, plafond 0,25-0,45 ms)
* instrument livré : `outils/gpu/mesure/banc-marlin-plancher.py` (≤ 3 min, Manon) — GEMV Marlin servi (`nvfp4_gemv_marlin_gateup` + `nvfp4_gemv_marlin`, formes Coder, piles synthétiques = mêmes octets, routage à D = 42 distincts exacts ou réel `--routages`), sous graphe CUDA : `gateup`, `down`, `couche` (les deux enchaînés), `8 couches` (8 piles distinctes enchaînées, par couche), `l2_froid` (balayage 256 Mo entre rejeux) ; To/s contre plancher et pic ; 2 tests à sec.

## 1. Les quatre endroits possibles des 6 % (0,44 ms à 1,55 ; 0,9 ms au pic)
| candidat | mécanisme | ce que le banc rend | au bit ? |
|---|---|---|---|
| (a) rampe et queue de vague par lancement | chaque noyau commence sans rien en vol dans le pipeline mémoire et finit avec une dernière vague partielle : 2-3 µs par lancement, 2 lancements par couche, 96 par pas = 0,2-0,3 ms ; la dépendance gate·up → down interdit le recouvrement | `couche` − (`gateup` + `down`) ≈ 0 (sérialisés de toute façon) ; `8 couches` par couche = `couche` (la rampe ne s amortit pas entre couches dépendantes) ; la rampe se lit dans l écart To/s noyau seul contre plancher | **oui** : PDL (lancement programmatique dépendant, `cudaLaunchAttributeProgrammaticStreamSerialization` + `cudaGridDependencySynchronize()` dans le prologue du consommateur) laisse les blocs du noyau suivant se placer et charger leurs poids pendant la queue du précédent — aucune arithmétique ne change ; capturable dans un graphe (arêtes programmatiques, CUDA ≥ 12.3 ; à vérifier sur torch 2.14 / CUDA 13 par un test de capture) |
| (b) quantification des vagues | blocs = D × tuiles N : gate·up 42 × 12 = 504 blocs = 2,96 vagues de 170 SM (dernière vague pleine à 96 %) ; down 42 × 32 = 1 344 = 7,9 vagues | To/s de `gateup` contre `down` : si `down` est nettement plus proche du plancher, (b) pèse sur gate·up | oui (ordre des tuiles) — mais D est dicté par le routage, pas par nous : petit |
| (c) L2 | échelles, tables d experts, x relus par 42 experts : chauds en banc, froids entre deux couches en service ? | `l2_froid` − `couche` : > 2 % = le service est plus près du froid | — (mesure) |
| (d) horloge/puissance | à 2 700 verrouillé et 380 W, l horloge SM médiane servie est 2 520-2 690 (M2) ; le noyau borné mémoire perd ~1-2 % par −5 % d horloge (émission) | hors banc : Manon compare `-lgc 2700` et libre sur le même banc | — (régime) |
**Prédit** (écrit avant) : `gateup` + `down` isolés en graphe à 2 700 : **1,45-1,55 To/s** (94-100 % du plancher : le noyau isolé est meilleur que dans le pas) ; `couche` = somme + 2-4 µs ; `8 couches` = `couche` ± 1 µs ; `l2_froid` ≤ +2 %. Si tout cela tient, les 6 % du pas sont **(a) + (d)** : la rampe par dépendance (≈ 0,2-0,3 ms) plus l horloge sous plafond (≈ 0,1). **Réfuté** : `couche` ≥ 1,55 To/s en banc (le manque est entièrement dans le pas : régime d horloge, voisinage des autres noyaux — rien à faire dans Marlin) ; ou `8 couches` < `couche` − 3 µs (la rampe s amortit déjà entre couches : PDL n a pas d objet).

## 2. Le levier au bit : PDL sur la chaîne gate·up → down → (couche suivante)
Mécanisme : lancer `nvfp4_gemv_marlin` (down) avec l attribut programmatique ; dans son prologue, avant la première lecture de `act`, `cudaGridDependencySynchronize()` ; le noyau amont (gate·up) appelle `cudaTriggerProgrammaticLaunchCompletion()` quand ses dernières écritures sont enfilées. Les blocs de down chargent leurs POIDS (indépendants de `act`) pendant la queue de gate·up ; seule la lecture de `act` attend. Même chose entre down et le gate·up de la couche suivante (qui dépend de la norme, elle-même dépendante de down : deux niveaux — le gain porte surtout sur gate·up → down).
* **Invariant au bit** : les mêmes noyaux, les mêmes octets, le même ordre d accumulation ; seul l instant de lancement change → ids et logits au bit **par construction** ; test : sortie PDL == sortie sans PDL (`torch.equal`) sur 200 routages, en eager et sous graphe capturé ; test de capture (le graphe avec arêtes programmatiques se capture et se rejoue : sinon repli automatique, ligne de régime `marlin=pdl|serie`).
* **Plafond** : la rampe mesurée × 48 : **0,15-0,30 ms/pas (2-4 %)** ; prédit **−0,2 ms (−3 %)**, t/s 1 700 → 1 750 ; réfuté si le banc (`couche` avec PDL contre sans) ne rend pas ≥ 1,5 µs/couche, ou si la capture échoue sur ce torch/CUDA (alors : hors devis, on le dit).
* Opt-in `ACVRAM_MARLIN_PDL=1` d abord, `regime.VARIABLES`, défaut après ABBA ≥ +1 % et ids au bit b=1/b=12.

## 3. Ce qui n est pas un levier
Changer les tuiles ou l ordre des sommes intra-tuile (autre noyau, autre arithmétique) : pas au bit, hors de cette pièce ; W4A4 : refusé (C17). Le plancher 1,55 lui-même (87 % du pic) : c est la limite de `plancher-par-octets` sur cette carte — la dépasser n est pas un objectif de noyau.
