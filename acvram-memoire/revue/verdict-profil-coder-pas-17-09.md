## GLM `-k48-calibA` b=12 sous `bf16` — et pourquoi 540 et non 514
Deux bras discriminants ajoutés (même chaîne, 3 min) : `calibA` + `ACVRAM_PREFILL=w8a8` (l'ancien `a8`) = **539,4 t/s** → `ACVRAM_PREFILL` ne touche pas le décodage (prédiction poste7 tenue, écart 0,1 %) ; `-k48` sous `bf16` = **521,2 t/s** (514 le 16/09 : +1,4 % de dérive d'arbre/thermique). L'écart restant, **+3,5 % de `calibA` sur `-k48`**, est le converti : `regime_ligne()` identiques, manifestes identiques hors SNR (0 champ de format/clé/forme différent, 9 028 nvfp4 / 335 int8 / 341 bf16 dans les deux), seuls diffèrent `experts_sans_stats` (558 → 201) et les poids. Hypothèse non testée (5 min d'instrument) : la calibration change le routage, donc le nombre d'experts distincts touchés par pas et les octets lus par `gemv_grouped`. Cellule à publier : **539,5 t/s, 0,732 J** (rondes ×2, 1 787 pas, bridage 400 W pendant la fenêtre comme le 16/09) ; la ligne « 514 » du comparatif est à éditer, pas le régime.

## Réserves
- Seuil b=12 franchi de 2 points (52,0 contre 50) : la thèse « experts ≥ 50 % » n'est pas une marge, c'est un partage à égalité avec le reste ; le gain d'un noyau d'experts à b=12 est borné par ce reste (6,2 ms).
- `torch._grouped_mm` déroulé en boucle : **confirmé** par micro-test sous le verrou (E=128, T=16 384, K=2048, N=768, sm_120, torch 2.14) : 1 `aten::_grouped_mm` → 128 `aten::mm` (128 noyaux `cutlass_80…gemm_relu` + 128 `splitKreduce`) + 1 `Memcpy DtoH` (les `offs` relus sur l'hôte : une synchronisation par pile, 432 par prefill). C'est un repli, pas un noyau groupé : la moitié du gain prefill s'obtient sans nouveau noyau NVFP4 (GEMM groupé bf16 CUTLASS après déquant, ou `bmm` par pile) — et le noyau fusionné W4A16 de poste7 supprime les deux moitiés (déquant 50,8 ms + boucle 136 ms).
- Le profileur gonfle le pas nu (+23 % b=1, +31 % prefill) : les parts sont des rapports de temps GPU propres, la somme GPU (4,04 / 12,86 / 225,8 ms) est ≤ le pas nu — cohérent.
