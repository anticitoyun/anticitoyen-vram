## Ce qui est fait (poste1-11, ce commit)
* **Qui pose** : `acvram/engine/loader.py:load_model` appelle `eco.poser_pour_ce_processus()` avant le premier octet chargé — le serveur ET tout instrument qui charge un moteur (`certifie`, `capture-godets`, `energie_par_poste`, PPL) : une fois par processus, carte servie (`index_carte()`), mode = `mode_demande()`. Sans carte (`CUDA_VISIBLE_DEVICES=""`) : état « sans carte », rien n'est exécuté.
* **Qui rend** : `eco.Horloge.rendre()` (`-rgc`, une seule fois, seulement si ce processus a posé) — par `Engine.fermer()` (nouveau, `runner.py`), appelé au `shutdown` de l'application (`server/app.py`), par `atexit`, et sur SIGTERM/SIGINT (gestionnaire qui rend puis laisse l'ancien gestionnaire agir : SIGINT → KeyboardInterrupt, SIGTERM → sortie 143). Pas de relâchement à l'oisiveté ; C8 reste `ACVRAM_GOUVERNEUR=1`.
* **État nommé** : `regime()["eco"]` = {demandé, effectif, état, conforme} ; ligne de régime du moteur et `regime.regime_ligne()` : `eco=2700(2692)` conforme, `eco=2700(libre: refus sudo)` / `(3000: non pris)` sinon, `eco=2700(sans carte)` à sec. **Les instruments refusent de publier** : `outils/regime.py:exiger_regime_nominal` lève sur demandé ≠ effectif (même garde que « repli eager vu »), « sans carte » n'est pas une faute.
* **Configuration** : `~/.config/acvram/config.json` `{"eco": "2700"}` (défaut sans fichier : 2700 ; 2100, off acceptés ; valeur inconnue → défaut, dit) ; `ACVRAM_ECO` prime (bras A/B, `regime.VARIABLES`, jamais le service) ; `acvram eco 2700|2100|off` **écrit** config.json puis applique : carte libre → `-lgc`/`-rgc` tout de suite ; carte tenue par un pair → 2700/2100 différés à son prochain démarrage (dit), **`off` appliqué quand même** (`-rgc` sous le serveur qui tourne, nommé) ; `acvram eco etat` lit. `tests/conftest.py` pose `ACVRAM_ECO=off` par défaut : la suite n'est pas un service.
* **Lecture de l'horloge corrigée** (défaut trouvé par poste2 23 h : `clocks_event_reasons.applications_clocks_setting` reste « Not Active » sous `-lgc` sur ce pilote, la ligne disait `horloge=libre` sous 2 692 MHz) : `lire_horloge` lit `clocks.sm, clocks.max.sm, clocks_event_reasons.gpu_idle` ; le **verrou vient de l'état posé** `/tmp/acvram-eco-<index>.json` ({mode, pid, depuis}, écrit par `Horloge.poser` et `eco.regler`, retiré au rendu) **vérifié contre clocks.sm ± 30 MHz** (2 700 se lit 2 692) ; sans état posé : `libre`, sauf carte oisive à > 1 000 MHz = `-lgc` posé hors de ce poste, dit `lgc2692?`. L'effectif est toujours l'horloge LUE, jamais la mémoire d'un réglage.
* **doctor** : `_doctor_eco` — mode demandé et sa source, droit `sudo -n -l nvidia-smi` (sinon la ligne sudoers à poser, imprimée), puis, carte visible, libre et mode ≠ off, **l'effet** : `-lgc` → lecture → `-rgc` (« ok -lgc 2700,2700 pris (lu 2692 MHz), -rgc rendu » / ECHEC nommé) ; carte tenue par un pair : l'effet n'est pas vérifié, dit. `install.sh` imprime la ligne sudoers quand le droit manque (jamais installée par l'arbre de dev).
* **Tests à sec** (`tests/test_eco_defaut.py`, 7 ; `test_eco_horloge.py` rejoué sur la nouvelle lecture ; 36 passed avec `test_regime_noyaux`, 98 avec serveur/PPL/MLA) : faux `nvidia-smi`/`sudo` qui enregistrent — pose au chargement (`-lgc 2700,2700`, état écrit), rendu à `Engine.fermer` (**casse si l'on retire le `-rgc` de `fermer`** : le corps réel de la méthode est exercé), rendu sur SIGTERM (sous-processus réel, journal : `-lgc` puis `-rgc` en dernier, sortie ≠ 0), refus sudo → `eco=2700(libre: refus sudo)`, aucun `-rgc`, instrument qui refuse (`RuntimeError` « eco demandé 2700 ≠ effectif ») ; config (précédence variable > fichier > défaut, JSON cassé → {}), lecture par état + clocks.sm (tenu / non tenu / libre / incertain), CLI (2100 différé sous un pair, off appliqué, 2700 appliqué carte libre).
