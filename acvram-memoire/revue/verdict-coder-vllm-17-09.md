## Ce que les falsifications disent
- **Poids, pas activations.** Scellé : W4A16 privé 1,015-1,035, « la perte de 15 % du W4A4 vient des activations 4 bits ». Mesuré 1,1227 : le checkpoint communautaire (calibration ModelOpt sur un corpus inconnu, KV fp8 de série) perd 12 % avant toute activation 4 bits. La même architecture convertie par acvram sans calibration donne 1,0144 : la perte est dans les tenseurs du checkpoint, pas dans le format NVFP4 ni dans les noyaux vLLM. Un ModelOpt propre aurait tranché entre « ModelOpt » et « ce checkpoint » ; il est refusé (`poste7-modelopt-coder-export-17-09.md`, `verdict-modelopt-coder-tf4-17-09.md`) — la cellule reste sur le communautaire, non classée dans ses deux régimes.
- **KV fp8 ne coûte rien à 2048** : 0,0008 et 0,0070 ≤ 0,010 ; le régime « communautaire par défaut » se publie avec KV fp8 sans réserve.
- **Marlin plus rapide que CUTLASS en décodage sur sm_120** (scellé : l'inverse, W4A16 b=12 750-900). Décodage borné par la bande passante des poids : Marlin (déquant W4 → bf16 dans le GEMM, MoE fusionné Marlin) lit les mêmes octets sans la quantification des activations par jeton du chemin CUTLASS ; le W4A4 ne l'emporte qu'en prefill, où le GEMM FP4×FP4 compte (×1,68). Régime vLLM à retenir dans la table : **W4A16 Marlin** pour les vitesses, les deux pour la qualité (identiquement non classées).
- Public : les médianes (1,1656 / 1,2010) dépassent les géos (1,0876 / 1,1160) — distribution asymétrique des rapports par fenêtre sur le public (fenêtres de code court très bien prédites par bf16), pas sur le privé ; les deux colonnes sont publiées, la géo classe (règle poste7).
