## দুটি ধারণা

একটি নির্দিষ্ট মেশিনের জন্য তৈরি:

| | |
|---|---|
| প্রসেসর | Intel Core i9-14900K (8টি P-কোর + 16টি E-কোর) |
| মাদারবোর্ড | ASUS ROG Maximus Z790 Dark Hero |
| মেমোরি | 96 GB DDR5 |
| GPU 0 | ASUS RTX 5090 Astral LC OC, 32 GB — Blackwell, `sm_120` |
| GPU 1 | ASUS RTX 3080 Ti, 12 GB — Ampere, `sm_86` |
| সিস্টেম | Ubuntu 26.04 LTS (CUDA 13); দুটি কার্ডই PCIe x8/x8-এ, পাওয়ার-সীমা 400 W / 275 W |

**প্রতিটি GPU-র জন্য একটি ফরম্যাট।** RTX 5090-এ FP4 টেনসর কোর আছে; RTX 3080 Ti-তে সেগুলো নেই, FP8-ও নেই। দুটিকে একটি সাধারণ ফরম্যাটে মেলালে 5090-এর সামর্থ্য অপচয় হতো। তাই কনভার্টার *একই মডেল দুবার* লেখে, প্রতিটি গন্তব্য বাস্তবে যে ফরম্যাট কাজে লাগাতে পারে সেই ফরম্যাটে:

| | RTX 5090 | RTX 3080 Ti |
|---|---|---|
| ওয়েট | **NVFP4** — E2M1 + প্রতি 16টিতে FP8 E4M3 স্কেল | **INT4** — uint4 + প্রতি 128টিতে fp16 স্কেল ও জিরো-পয়েন্ট |
| প্রতি ওয়েটে বিট | 4.50 | 4.16 |
| BF16-এর তুলনায় | ×3.56 ছোট | ×3.85 ছোট |
| গণনার ধরন | FP4 টেনসর কোর | কার্নেলের ভেতরে FP16-এ ডিকোয়ান্টাইজ করা, FP16 টেনসর কোর |
| KV ক্যাশ | INT8 | INT8 |

প্রতি ওয়েটে 4.5 বিট হিসেবে 32 GB VRAM মোটামুটি **56 বিলিয়ন প্যারামিটার** ধারণ করে, যেখানে BF16-এ ধরে মাত্র 16 বিলিয়ন। দুটি কার্ড মিলিয়ে, হোস্ট মেমোরি স্পর্শ করার আগেই প্রায় **78 বিলিয়ন প্যারামিটার** রেসিডেন্ট থাকে।

**মেমোরি একটি স্তরবিন্যাস, দেয়াল নয়।** তিনটি স্তর, এবং মডেলটি এঁটে যাবে বলে আশা না করে প্ল্যানার প্রতিটি স্তরের প্রকৃত খরচ মেপে দেখে:

```
RTX 5090     32 GB   ~1790 GB/s     NVFP4
RTX 3080 Ti  12 GB    ~912 GB/s     INT4
হোস্ট DDR5   96 GB   PCIe বা DDR দ্বারা সীমিত
```

## দ্রুত শুরু

```bash
./install.sh                       # ভার্চুয়াল এনভায়রনমেন্ট + torch cu128 + acvram
acvram doctor                      # এই মেশিন প্রস্তুত কি না, এবং কীসের জন্য
acvram detect                      # এখানে আসলে কী আছে

acvram plan  ~/models/Qwen3-32B                     # প্রতিটি লেয়ার কোথায় যাবে
acvram convert ~/models/Qwen3-32B -o ~/acv/qwen3-32b
acvram serve ~/acv/qwen3-32b --port 8000
```

যেকোনো OpenAI ক্লায়েন্ট সঙ্গে সঙ্গেই এতে যুক্ত হতে পারে:

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-32b","messages":[{"role":"user","content":"নমস্কার"}],"stream":true}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="অব্যবহৃত")
client.chat.completions.create(model="qwen3-32b",
                               messages=[{"role": "user", "content": "নমস্কার"}])
```

## ইনস্টল

সোর্স থেকে (যেকোনো প্ল্যাটফর্মে):

```bash
git clone https://github.com/anticitoyun/anticitoyen-vram.git && cd anticitoyen-vram
./install.sh
```

অথবা প্যাকেজের মাধ্যমে, প্রতিটি [GitHub রিলিজ](https://github.com/anticitoyun/anticitoyen-vram/releases/latest)-এ সংযুক্ত একটি ফাইল দিয়ে:

| চ্যানেল | রিলিজে সংযুক্ত ফাইল | কমান্ড |
|---|---|---|
| Debian / Ubuntu (.deb) | `acvram_<version>_amd64.deb` | `sudo dpkg -i acvram_<version>_amd64.deb` |
| Arch (AUR) | `aur-<version>.tar.gz` (PKGBUILD + .SRCINFO) | `tar xzf aur-<version>.tar.gz && cd acvram && makepkg -si` |
| Fedora / COPR (RPM) | `.rpm` / `.src.rpm` (নাম `rpmbuild` তৈরি করে, নির্দিষ্ট নয়) | `sudo rpm -i acvram-<version>-1.*.noarch.rpm` (অথবা `rpmbuild --rebuild *.src.rpm` দিয়ে `.src.rpm` থেকে) |
| Flatpak | `acvram-<version>.flatpak` | `flatpak install acvram-<version>.flatpak` |

Pip-এ কোনো প্যাকেজ প্রকাশ করা হয় না (কোনো হুইল তৈরি হয় না): `pip install -e '.[dev]'` সোর্সের একটি ক্লোন থেকে ইনস্টল করে, ঠিক `./install.sh`-এর মতো।

## `acvram plan` কী বলে

যেকোনো ডাউনলোডের আগেই প্ল্যানারটি চালিয়ে দেখা উচিত। একটি মডেল এই মেশিনে আদৌ ব্যবহারযোগ্য কি না, তা যে প্রশ্নগুলোর ওপর নির্ভর করে, এটি সেগুলোর উত্তর দেয়:

```
$ acvram plan ~/models/Llama-3.3-70B --max-model-len 32768 --max-seqs 4

  স্তর    ফরম্যাট     ধারণক্ষমতা    ওয়েট          KV  অংশ
  cuda:0  nvfp4        30.3 GiB    25.5 GiB   4.5 GiB  লেয়ার 0-58
  cuda:1  int4_awq     10.9 GiB     8.7 GiB   1.6 GiB  লেয়ার 59-79
  cpu     nvfp4        74.8 GiB     3.4 GiB      0 B   -

  মোট ওয়েট           37.6 GiB
  প্রতি টোকেনে পঠিত   35.1 GiB
  প্রতি টোকেনে KV     162.5 KiB  -> 39,843 টোকেন ক্যাশে
  হোস্ট RAM-এ MLP     55-58

  ডিকোড অনুমান       17.8 টোকেন/s  (ব্যাচ 1)
  প্রিফিল অনুমান      847 টোকেন/s
```

এটি প্রথম যে কনফিগারেশনটি এঁটে যায় সেখানেই থেমে না গিয়ে পুরো কনফিগারেশন-পরিসর অন্বেষণ করে, এবং এর দুটি সিদ্ধান্ত এতটাই প্রত্যাশাবিরোধী যে সেগুলো স্পষ্ট করে বলা দরকার:

* **মডেল শুধু 5090-এই এঁটে গেলে এটি 3080 Ti-কে অলস রাখে।** পাইপলাইনের ধাপগুলো পরপর ক্রমানুসারে চলে: 1790 GB/s-এর পাইপলাইনে 912 GB/s-এর একটি ধাপ যোগ করলে একক-স্ট্রিম ডিকোড ধীর হয়ে যায়। `--gpus all` দিয়ে জোর করে ব্যবহার করানো যায়।
* **VRAM-এ ওয়েট রাখার জন্য এটি KV ক্যাশ ছোট করে।** ক্যাশকে দেওয়া প্রতিটি গিগাবাইট মানে PCIe বাসে ঠেলে দেওয়া এক গিগাবাইট ওয়েট, আর PCIe দিয়ে একটি ওয়েট পড়তে VRAM থেকে পড়ার তুলনায় মোটামুটি ত্রিশ গুণ খরচ হয়। ওপরের 70B মডেলে শুধু এই একটি আপসই ডিকোডকে 2.3 থেকে 17.8 টোকেন/s-এ নিয়ে যায়।

## গতি বাড়ানো

চারটি অপ্টিমাইজেশন, প্রতিটি শুধু স্টপওয়াচ দিয়ে নয়, সমতুল্যতার প্রমাণ দিয়েও যাচাই করা: যে অপ্টিমাইজেশন উত্তর বদলে দেয়, সেটি একটি বাগ।

ডেনস মডেলের NVFP4 লিনিয়ার লেয়ারগুলো ডিফল্টভাবে Marlin বিন্যাসের মধ্য দিয়ে যায় (b = 8-এ থ্রুপুট +57 থেকে +90%, TTFT +2 থেকে +4 ms, revue/poste6-piece147-verdict-24-09.md অনুযায়ী; ফলব্যাক `ACVRAM_PROJ_MARLIN=0`, দেখুন [CHANGELOG.md](../CHANGELOG.md))।

### স্পেকুলেটিভ ডিকোডিং (`--speculative`)

ব্যাচ আকার 1-এ একটি টোকেন ডিকোড করা মেমোরি-নির্ভর: মাত্র একটি টোকেন তৈরি করতে মেশিনটিকে প্রতিটি সক্রিয় ওয়েট পড়তে হয়। K-সংখ্যক প্রস্তাবিত টোকেন যাচাই করতে সেই একই ওয়েটগুলো **মাত্র একবার** পড়তে হয়। দুটি প্রস্তাবক:

* `ngram` (ডিফল্ট) — বর্তমান সাফিক্সটি কনটেক্সটের আগের অংশে খোঁজে এবং তার পরে যা এসেছিল তা প্রস্তাব করে। কোনো খরচ নেই, কোনো মডেলের প্রয়োজন নেই। আউটপুট যখন ইনপুটের পুনরাবৃত্তি করে তখন লাভজনক: কোড সম্পাদনা, RAG, সারসংক্ষেপ।
* `draft` — দ্বিতীয় একটি ডিভাইসে চলা একটি ছোট মডেল। এই রিগে সেই ডিভাইস হলো RTX 3080 Ti, যাকে প্ল্যানার 5090-এ এঁটে যাওয়া যেকোনো মডেলের ক্ষেত্রে ইচ্ছাকৃতভাবে অলস রাখে।

`mtp` (মডেলের `nextn` হেড) এবং `auto`-ও আছে; বর্তমান অবস্থায় লাভজনক নয় এবং ডিফল্টভাবে সক্রিয় নয় — দেখুন `docs/ARCHITECTURE.md`।

গ্রহণ-প্রক্রিয়া নির্ভুল, আনুমানিক নয়: একটি প্রস্তাব `min(1, p/q)` সম্ভাবনায় গৃহীত হয়, আর প্রত্যাখ্যাত হলে `p - q`-এর স্বাভাবিকীকৃত ধনাত্মক অংশ থেকে পুনরায় নমুনা নেওয়া হয়। ইচ্ছাকৃতভাবে ভুলভাবে ক্যালিব্রেট করা একটি ড্রাফটের বিপরীতে 40,000 বার নমুনা নিয়ে মাপা হয়েছে: নির্গত বণ্টন লক্ষ্য বণ্টন থেকে 0.002 টোটাল ভেরিয়েশনের মধ্যে থাকে — স্পেকুলেশন গতি কেনে, কখনো ভিন্ন উত্তর নয়।

```
খেলনা মডেল, greedy, k=4       ধাপ   টোকেন/ধাপ   আউটপুট
  স্পেকুলেশন ছাড়া               23         1.00   রেফারেন্স
  n-gram                         13         1.77   অভিন্ন
  draft (= লক্ষ্য)                5         4.60   অভিন্ন
```

### প্রিফিক্স ক্যাশ (ডিফল্টভাবে চালু)

ব্লকগুলো তাদের টোকেন-অংশের *শৃঙ্খলিত* হ্যাশ দিয়ে চিহ্নিত হয়: একই সিস্টেম প্রম্পট ভাগ করে নেওয়া দুটি অনুরোধ তার ব্লকগুলোও ভাগ করে নেয়, এবং দ্বিতীয়টিকে আর সেগুলো আগে থেকে গণনা করতে হয় না। শৃঙ্খলন অপরিহার্য: ভিন্ন কনটেক্সটে একই ষোলোটি টোকেন একই কী ও ভ্যালু ধারণ করে না, এবং শুধু অংশটির হ্যাশ নিলে এক সিকোয়েন্সের ক্যাশ অন্য সিকোয়েন্সকে দেওয়া হয়ে যেত।

মুক্ত করা কোনো ব্লকের বিষয়বস্তু শনাক্তযোগ্য থাকলে সেটি মুক্ত-ব্লকের তালিকায় না গিয়ে একটি LRU সারিতে যোগ দেয়: এভাবে ক্যাশ এক অনুরোধ থেকে আরেক অনুরোধে টিকে থাকে, অথচ যে বরাদ্দ সে দিতে পারত তা কখনো প্রত্যাখ্যান করে না।

### হোস্ট স্তরে গণনা (`--host-exec`)

যে লেয়ারের ওয়েট RAM-এ থাকে, সেটিকে GPU-তে কপি করা যায় অথবা সেখানেই গণনা করা যায়। দুটি পথই মেমোরি-নির্ভর এবং একই বাইট পড়ে: যার বাস বেশি চওড়া, সেটিই দ্রুততর — PCIe 5.0 x16 মোটামুটি 54 GB/s দেয়, ডুয়াল-চ্যানেল DDR5 মোটামুটি 70 GB/s — আর সেখানেই গণনা করলে বাড়তি সুবিধা হলো, GPU একটি কপির জন্য অপেক্ষা না করে মুক্ত থাকে।

এটি তখনই লাভজনক, যখন CPU প্যাক করা 4-বিট ওয়েট সরাসরি পড়ে। তাই AVX2 পথসহ একটি ছোট C++ কার্নেল (`acvram_cpu.cpp`, ctypes দিয়ে লোড হয়, Python হেডার বা ninja লাগে না)। এমনকি এর **স্কেলার** ফলব্যাক শাখাতেও এটি `dequantize() @ x`-কে INT4-এ 1.44 গুণ এবং NVFP4-এ 3.21 গুণ ব্যবধানে হারায়, কারণ দ্বিতীয়টি প্রথমে পুরো ম্যাট্রিক্সের একটি 32-বিট কপি লেখে।

Mistral-Large-123B-তে প্ল্যানারের অনুমান 1.35 থেকে বেড়ে 2.42 টোকেন/s হয়।

### মিশ্র প্রিসিশন (`--snr-floor`, ডিফল্টভাবে বন্ধ)

কনভার্টার প্রতিটি টেনসরের জন্য লেয়ার-আউটপুটের সিগন্যাল-টু-নয়েজ অনুপাত মাপে এবং যেগুলো `--snr-floor`-এর নিচে পড়ে সেগুলোকে একটি প্রশস্ততর ফরম্যাটে উন্নীত করতে পারে — মোট টেনসরের 15% সীমা এবং একটি সর্বোচ্চ মূল্যের মধ্যে (`--promotion-cout-max`, যোগ হওয়া মেবিবাইটে)।

ফ্লোরটি **ডিফল্টভাবে শূন্য**: কিছুই উন্নীত হয় না। ডিকোডিং মেমোরি-ব্যান্ডউইথ-নির্ভর, এবং `Huihui-Qwen3.8-27B`-এর ওপর করা পরিমাপ বিষয়টির নিষ্পত্তি করে — 25 dB ফ্লোরের খরচ 13.4% মেমোরি ও 10.6% থ্রুপুট (18.50 GiB ও 41.8 t/s, বিপরীতে 16.02 ও 46.2), বিনিময়ে পারপ্লেক্সিটিতে লাভ মাত্র 2.0% (42.591 বনাম 43.447, 16,383 টোকেনের কর্পাস)। গতির চেয়ে গুণমান বেশি গুরুত্বপূর্ণ হলে `--snr-floor 25` পুরোনো আচরণ ফিরিয়ে আনে।

### এবং `acvram eval`

সিগন্যাল-টু-নয়েজ অনুপাত ও লজিটের কোসাইন সাদৃশ্য আসলে আনুমানিক মাপকাঠি। `acvram eval REP [REP ...]` স্লাইডিং-উইন্ডো পারপ্লেক্সিটি মাপে, যাতে ফরম্যাট বাছাইয়ের সিদ্ধান্ত প্রমাণের ভিত্তিতে নেওয়া যায়:

```
$ acvram eval ~/acv/qwen3-32b-nvfp4 ~/acv/qwen3-32b-int4
  মডেল                     ppl     bpp        আকার     টোকেন
  qwen3-32b-nvfp4        6.412    4.51     17.4 GiB      8192
  qwen3-32b-int4         6.583    4.17     16.1 GiB      8192  (+2.7%)
```

## সংখ্যাগুলো কোথা থেকে আসে

ওপরে উল্লেখ করা প্রতিটি মান এই রিপোজিটরির কোড থেকে আসে এবং `pytest` দিয়ে যাচাই করা হয়। রেফারেন্স কার্নেল ব্যবহার করে CPU-তে নেওয়া পরিমাপ:

| ফরম্যাট | বিট/ওয়েট | ওয়েটের SNR | BF16-এর তুলনায় লজিট কোসাইন |
|---|---|---|---|
| BF16 | 16.00 | — | 1.0000 |
| INT8 | 8.19 | 44.6 dB | 0.9998 |
| NVFP4 | 4.50 | 20.4 dB | 0.9664 |
| INT4 | 4.16 | 20.0 dB | 0.9427 |
| INT4 + Hadamard | 4.16 | 21.0 dB | 0.9582 |

এই পরিমাপ থেকে পাওয়া দুটি পর্যবেক্ষণ ডিফল্ট মানগুলো বদলে দিয়েছে:

* **Hadamard ঘূর্ণন INT4-কে সাহায্য করে, NVFP4-কে নয়।** INT4-এর 128-এর গ্রুপগুলো একটি বিচ্ছিন্ন আউটলায়ার চ্যানেল শোষণ করতে পারে না, তাই চরম মানগুলো ছড়িয়ে দেওয়ার জন্য প্রতি অ্যাক্টিভেশনে একটি n log n রূপান্তর সার্থক। NVFP4-এর 16-এর ব্লকগুলো আগে থেকেই নিজস্ব স্কেল বহন করে। তাই `--hadamard auto`, যা এটি কেবল INT4-এ প্রয়োগ করে।
* **KV ক্যাশের জন্য INT8, FP8 E4M3-কে হারায়**, সমান আকারে 44 dB বনাম 32 dB, কারণ প্রতি-(টোকেন, হেড) স্কেল আগেই সেই ডায়নামিক রেঞ্জ সরবরাহ করে, যার জন্য FP8 এক্সপোনেন্ট বিট খরচ করে। তাই 5090 FP8 চালাতে পারলেও দুটি কার্ডই INT8 KV ক্যাশ ব্যবহার করে। একটি `k8v4` ফরম্যাট (INT4 ভ্যালু, ক্যাশের বাইট −22%) বিকল্প হিসেবে আছে, তবে **যোগ্যতা যাচাই হয়নি** — দেখুন `docs/ARCHITECTURE.md`।

> **সংশোধনী (2026-09-23)।** এতদিন প্রকাশিত vLLM তুলনা (b=12: 1,782 বনাম 1,634 t/s; b=1: 290.6) HTTP-তে মাপা acvram-কে **অফলাইনে** মাপা vLLM-এর (`LLM().generate()`) সঙ্গে তুলনা করেছিল, এবং 2026-09-22-এর সংশোধনী ভুলভাবে দাবি করেছিল যে vLLM ঘরটি `vllm serve`-এর মাধ্যমে মাপা হয়েছিল। 2026-09-23-এ: দুটির জন্যই একই HTTP ক্লায়েন্ট, এবং দুটির জন্যই `-lgc` নির্ধারিত (acvram চালু হওয়ার সময় নিজেরটা নির্ধারণ করে, `vllm serve` করে না: এই সতর্কতা ছাড়া vLLM ~2,930 MHz-এ চলছিল, বিপরীতে ~2,650)। ফলাফল নোট ²-এ: b=12-এ vLLM 9.1% এগিয়ে।

2026-09-14-এর সকালে একই ঘরে acvram ছিল 630 t/s ও 0.619 J/টোকেনে: উন্নতি এসেছে Blackwell-এর নেটিভ FP4 MMA (`mma.sync … kind::mxf4nvf4`, bf16-এর তুলনায় ×7.9), ব্যাচ-বাকেট অনুযায়ী grouped-GEMM MoE, একক-কার্নেল রাউটিং (প্রতি ধাপে 3,677 → 1,517 লঞ্চ), এবং প্রজেকশনের জন্য একটি সরু টেনসর-কোর GEMM থেকে। প্রতিটি সংখ্যার নোট আছে `acvram-memoire/revue/`-এ, পরিমাপের আগে সিল করা পূর্বাভাস, পরিমাপ-যন্ত্র ও তার রেজিমসহ — রেজিমবিহীন কোনো সংখ্যা প্রকাশ করা হয় না।

acvram যেখানে এগিয়ে: নেটিভ sm_120 NVFP4-এ MLA মডেল (GLM-4.7-Flash), যা vLLM কেবল FP8-এ সার্ভ করে (b=1: চালু অবস্থায় 165.35 t/s); আর যে মডেলগুলো VRAM-এ আঁটে না। একক-সিকোয়েন্স ডিকোড এর মধ্যে পড়ে না: স্পেকুলেশন ছাড়া সেখানে acvram vLLM-এর চেয়ে 9.7% এগিয়ে (নোট ³), থ্রুপুটে llama.cpp-এর চেয়ে 5.8% পিছিয়ে কিন্তু শক্তিতে 13.4% এগিয়ে (নোট ⁴)। বড় ব্যাচে, VRAM-এ এঁটে যাওয়া একটি MoE মডেলে, b=12-এ vLLM থ্রুপুটে সমান (1,995.1 বনাম 2,027.0 t/s, 2σ-এর নিচে, নোট ²) কিন্তু J/টোকেনে 7.0% সুবিধা ধরে রাখে; সেখানে acvram 1,540 t/s (0.6.34) থেকে 1,995 (0.6.38)-এ উন্নীত হয়েছে।

## বর্তমান অবস্থা

সংস্করণ 0.6.38। সবকিছু 5090-এ চলে: `sm_120a` (নেটিভ FP4) ও `sm_86`-এর জন্য কম্পাইল করা CUDA কার্নেল, CUDA গ্রাফ, NVFP4/INT8/INT4 কোয়ান্টাইজেশন, HTTP সার্ভার। চালু থাকা সুরক্ষাব্যবস্থা: কাজের সেশনগুলোর কাছে কার্ডটি অদৃশ্য (`CUDA_VISIBLE_DEVICES` খালি) এবং কেবল `outils/carte.sh` লকের অধীনে একবারে একটি পরিমাপকে এটি ধার দেয়; একটি পর্যবেক্ষক লকের বাইরের যেকোনো প্রবেশ লগ করে; একাধিক কার্ড জুড়ে চলা বা 10 s-এর কম সময়ের শক্তি-পরিমাপ বাতিল বলে গণ্য হয়; অবনমিত রেজিমে লোড হওয়া মডেল তা জানিয়ে দেয় এবং কোনো দ্বৈরথে অংশ নেয় না।

4,107টি টেস্ট (`pytest --collect-only -q`, CPU-তে এক মিনিট; GPU টেস্ট কেবল `carte.sh`-এর অধীনে চলে)। কাজের লগ: `acvram-memoire/` (নিয়মাবলি, ডিরেক্টরি, নোটবুক, কয়েকশো রিভিউ নোট)।
