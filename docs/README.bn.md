স্তরবিন্যাস হিসেবে দেখে এবং প্রতিটি GPU-কে সেই সংখ্যাগত ফরম্যাট দেয় যা তার
সিলিকন সবচেয়ে ভালো পড়ে।

একটি নির্দিষ্ট মেশিনের জন্য তৈরি:

| | |
|---|---|
| প্রসেসর | Intel Core i9-14900K (8 P-কোর + 16 E-কোর) |
| মাদারবোর্ড | ASUS ROG Maximus Z790 Dark Hero |

## দুটি ধারণা

**প্রতি GPU-তে একটি ফরম্যাট।** RTX 5090-এ FP4 টেনসর কোর আছে; RTX 3080 Ti-তে
নেই, FP8-ও নেই। দুটিকে একটি সাধারণ ফরম্যাটে আনলে 5090 নষ্ট হতো। তাই
কনভার্টার *একই মডেল দুবার* লেখে, সেই ফরম্যাটে যা প্রতিটি গন্তব্য সত্যিই কাজে
লাগাতে পারে:

| | RTX 5090 | RTX 3080 Ti |
|---|---|---|
| ওজন | **NVFP4** — E2M1 + প্রতি 16-তে FP8 E4M3 স্কেল | **INT4** — uint4 + প্রতি 128-এ fp16 স্কেল ও শূন্য |
| প্রতি ওজনে বিট | 4,50 | 4,16 |
| BF16-এর তুলনায় | ×3,56 ছোট | ×3,85 ছোট |
| গণনার ধরন | FP4 টেনসর কোর | কার্নেলে FP16-এ ডিকোয়ান্টাইজ, FP16 টেনসর কোর |
| KV ক্যাশ | INT8 | INT8 |

প্রতি ওজনে 4,5 বিটে 32 GB VRAM-এ প্রায় **56 বিলিয়ন প্যারামিটার** ধরে, যেখানে
BF16-এ 16 বিলিয়ন। দুটি কার্ড মিলিয়ে RAM ছোঁয়ার আগেই তা প্রায় **78 বিলিয়ন
আবাসিক প্যারামিটার**।

**মেমোরি একটি স্তরবিন্যাস, দেয়াল নয়।** তিনটি স্তর, আর পরিকল্পক মডেল ধরবে
এই আশা না করে প্রতিটির খরচ মাপে:

```
RTX 5090     32 Go   ~1790 Go/s     NVFP4
RTX 3080 Ti  12 Go    ~912 Go/s     INT4
DDR5 hôte    96 Go   limité par le PCIe ou la DDR
```

## দ্রুত শুরু

```bash
./install.sh                       # environnement virtuel + torch cu128 + acvram
acvram doctor                      # cette machine est-elle prête, et pour quoi
acvram detect                      # qu'y a-t-il réellement ici

acvram plan  ~/modeles/Qwen3-32B                    # où irait chaque couche
acvram convert ~/modeles/Qwen3-32B -o ~/acv/qwen3-32b
acvram serve ~/acv/qwen3-32b --port 8000
```

এরপর যেকোনো OpenAI ক্লায়েন্ট যুক্ত হয়:

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-32b","messages":[{"role":"user","content":"Bonjour"}],"stream":true}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="inutilise")
client.chat.completions.create(model="qwen3-32b",
                               messages=[{"role": "user", "content": "Bonjour"}])
```

## `acvram plan` কী বলে

যেকোনো ডাউনলোডের আগে পরিকল্পক চালানো উচিত। এটি সেই প্রশ্নগুলোর উত্তর দেয় যা
ঠিক করে একটি মডেল এই মেশিনে ব্যবহারযোগ্য কি না:

```
$ acvram plan ~/modeles/Llama-3.3-70B --max-model-len 32768 --max-seqs 4

  etage   format      capacite      poids         KV  tranche
  cuda:0  nvfp4        30,3 Gio   25,5 Gio   4,5 Gio  couches 0-58
  cuda:1  int4_awq     10,9 Gio    8,7 Gio   1,6 Gio  couches 59-79
  cpu     nvfp4        74,8 Gio    3,4 Gio       0 o  -

  poids au total     37,6 Gio
  lu par jeton       35,1 Gio
  KV par jeton       162,5 Kio  -> 39 843 jetons en cache
  MLP en RAM hote    55-58

  decodage estime    17,8 jetons/s  (lot de 1)
  prefill estime     847 jetons/s
```

এটি প্রথম যে কনফিগারেশন ধরে তাতে না থেমে পুরো কনফিগারেশন স্পেস খোঁজে, আর
এর দুটি সিদ্ধান্ত এতটাই স্বজ্ঞাবিরোধী যে বলা দরকার:

* **কোনো মডেল একা 5090-এ ধরলে এটি 3080 Ti-কে অব্যবহৃত রাখে।** একটি
  পাইপলাইনের অংশগুলো ক্রমে চলে: 1790 GB/s পাইপলাইনে 912 GB/s-এর একটি ধাপ
  যোগ করলে একক-স্ট্রিম ডিকোডিং ধীর হয়। `--gpus all` দিয়ে জোর করা যায়।
* **ওজন VRAM-এ রাখতে এটি KV ক্যাশ ছোট করে।** ক্যাশে দেওয়া প্রতিটি
  গিগাবাইট হলো PCIe বাসে ঠেলে দেওয়া এক গিগাবাইট ওজন, আর PCIe দিয়ে একটি
  ওজন পড়া VRAM থেকে পড়ার প্রায় ত্রিশ গুণ খরচ। উপরের 70B-তে শুধু এই
  আপসটিই 2,3 থেকে 17,8 টোকেন/সে-তে নিয়ে যায়।

## দ্রুত চলা

চারটি অপ্টিমাইজেশন, প্রতিটি শুধু স্টপওয়াচ নয়, সমতুল্যতার প্রমাণে যাচাই
করা: যে অপ্টিমাইজেশন উত্তর বদলায়, তা একটি বাগ।

### অনুমানভিত্তিক ডিকোডিং (`--speculative`)

আকার 1-এর ব্যাচে একটি টোকেন ডিকোড করা মেমোরি-সীমিত: মেশিন একটি টোকেনের
জন্য সব সক্রিয় ওজন পড়ে। প্রস্তাবিত K টোকেন যাচাই করলে সেই একই ওজন **একবারই**
পড়া হয়। দুটি প্রস্তাবক:

* `ngram` (ডিফল্ট) — বর্তমান প্রত্যয়টি প্রসঙ্গের আগের অংশে খোঁজে এবং তার পরে
  যা এসেছিল তা প্রস্তাব করে। কোনো খরচ নেই, কোনো মডেল লাগে না। আউটপুট যখন
  ইনপুট নকল করে তখন লাভজনক: কোড সম্পাদনা, RAG, সারসংক্ষেপ।
* `draft` — দ্বিতীয় ডিভাইসে একটি ছোট মডেল। এই রিগে সেই ডিভাইসটি
  RTX 3080 Ti, যাকে পরিকল্পক 5090-এ ধরা প্রতিটি মডেলের জন্য ইচ্ছাকৃতভাবে
  অলস রাখে।

গ্রহণ নির্ভুল, আনুমানিক নয়: একটি প্রস্তাব `min(1, p/q)` সম্ভাবনায় গৃহীত হয়
এবং প্রত্যাখ্যান `p - q`-এর স্বাভাবিকীকৃত ধনাত্মক অংশ থেকে পুনর্নমুনা নেয়।
ইচ্ছাকৃতভাবে ভুল ক্যালিব্রেট করা খসড়ার বিরুদ্ধে 40 000 ড্রয়ে মাপা হয়েছে,
নির্গত বণ্টন লক্ষ্য থেকে 0,002 মোট বিচ্যুতির মধ্যে থাকে — অনুমান গতি কেনে,
কখনো ভিন্ন উত্তর নয়।

```
modele jouet, glouton, k=4    etapes   jetons/etape   sortie
  sans speculation                23           1,00   reference
  n-grammes                       13           1,77   identique
  brouillon (= cible)              5           4,60   identique
```

### প্রিফিক্স ক্যাশ (ডিফল্টে সক্রিয়)

ব্লকগুলো তাদের টোকেন অংশের *শৃঙ্খলিত* হ্যাশ দিয়ে ঠিকানাযুক্ত: একটি সিস্টেম
নির্দেশ ভাগ করা দুটি অনুরোধ তার ব্লকও ভাগ করে, আর দ্বিতীয়টিকে সেগুলো আগে
থেকে হিসাব করতে হয় না। শৃঙ্খলন অপরিহার্য: ভিন্ন প্রসঙ্গে একই ষোলোটি টোকেনে
একই কী ও মান থাকে না, আর শুধু অংশটি হ্যাশ করলে এক সিকোয়েন্সের ক্যাশ অন্যকে
পরিবেশন করা হতো।

মুক্ত করা ব্লক যার বিষয়বস্তু এখনো শনাক্তযোগ্য, তা মুক্ত তালিকার বদলে LRU
সারিতে যায়: ক্যাশ এভাবে অনুরোধের মাঝে টিকে থাকে, যে বরাদ্দ সে দিতে পারত তা
কখনো প্রত্যাখ্যান না করে।

### হোস্ট স্তরে গণনা (`--host-exec`)

যে স্তরের ওজন RAM-এ আছে তা GPU-তে কপি করা যায় বা সেখানেই গণনা করা যায়।
দুটি পথই মেমোরি-সীমিত এবং একই বাইট পড়ে: দ্রুততর সেটি যার বাস প্রশস্ত —
PCIe 5.0 x16 প্রায় 54 GB/s দেয়, ডুয়াল-চ্যানেল DDR5 প্রায় 70 GB/s — আর
সেখানেই গণনা করলে GPU-কে কপির জন্য অপেক্ষা করানোর বদলে সে মুক্ত থাকে।

এটি তখনই সার্থক যখন প্রসেসর 4-বিট প্যাক করা ওজন সরাসরি পড়ে। তাই AVX2 পথসহ
একটি ছোট C++ কার্নেল (`acvram_cpu.cpp`, ctypes দিয়ে লোড, Python হেডার বা
ninja ছাড়া)। তার **স্কেলার** ফলব্যাক শাখাতেও এটি `dequantize() @ x`-কে
INT4-এ 1,44 ও NVFP4-এ 3,21 গুণে হারায়, কারণ পরেরটি আগে পুরো ম্যাট্রিক্সের
32-বিট কপি লেখে।

Mistral-Large-123B-তে পরিকল্পকের অনুমান 1,35 থেকে 2,42 টোকেন/সে হয়।

### মিশ্র নির্ভুলতা (`--snr-floor`, ডিফল্টে বন্ধ)

কনভার্টার প্রতিটি টেনসরের জন্য স্তরের আউটপুটে সংকেত/গোলমাল অনুপাত মাপে এবং
`--snr-floor`-এর নিচে পড়া টেনসরগুলোকে প্রশস্ত ফরম্যাটে উন্নীত করতে পারে,
টেনসরের 15 % ও একটি মূল্যসীমার (`--promotion-cout-max`, যোগ করা মেবিবাইটে)
মধ্যে।

সীমাটি **ডিফল্টে শূন্য**: কিছুই উন্নীত হয় না। ডিকোডিং মেমোরি ব্যান্ডউইডথে
সীমিত, আর `Huihui-Qwen3.8-27B`-এ পরিমাপ সিদ্ধান্ত দেয় — 25 dB সীমা 2,0 %
পারপ্লেক্সিটির (16 383 টোকেনের কর্পাসে 42,591 বনাম 43,447) বিনিময়ে 13,4 %
মেমোরি ও 10,6 % থ্রুপুট (16,02 ও 46,2-এর তুলনায় 18,50 GiB ও 41,8 t/s) খরচ
করে। মান গতির চেয়ে বড় হলে `--snr-floor 25` পুরনো আচরণ ফেরায়।

### এবং `acvram eval`

সংকেত/গোলমাল অনুপাত ও লজিট কোসাইন আসন্ন মান।
`acvram eval DIR [DIR ...]` স্লাইডিং উইন্ডোতে পারপ্লেক্সিটি মাপে, যাতে
ফরম্যাটের পছন্দ প্রমাণে স্থির হয়:

```
$ acvram eval ~/acv/qwen3-32b-nvfp4 ~/acv/qwen3-32b-int4
  modele                   ppl     bpp      taille    jetons
  qwen3-32b-nvfp4        6,412    4,51    17,4 Gio      8192
  qwen3-32b-int4         6,583    4,17    16,1 Gio      8192  (+2,7 %)
```

## HTTP এন্ডপয়েন্ট

| এন্ডপয়েন্ট | নোট |
|---|---|
| `POST /v1/chat/completions` | SSE স্ট্রিম বা একক উত্তর; মডেলের চ্যাট টেমপ্লেট ব্যবহার করে |
| `POST /v1/completions` | টেক্সট বা টোকেন আইডি হিসেবে প্রম্পট |
| `POST /v1/embeddings` | চূড়ান্ত লুকানো অবস্থার গড়, L2-স্বাভাবিকীকৃত, `dimensions` মান্য |
| `GET /v1/models` | সাথে একটি `acvram` ব্লক: ফরম্যাট, ডিভাইস, KV ক্যাশের ধারণক্ষমতা |
| `GET /health`, `GET /metrics` | ডিকোডিং থ্রুপুট, KV ব্লকের দখল |

## সংখ্যাগুলো কোথা থেকে আসে

উপরে উদ্ধৃত প্রতিটি মান এই রিপোজিটরির কোড থেকে তৈরি ও `pytest` দিয়ে যাচাই
করা। রেফারেন্স কার্নেল দিয়ে প্রসেসরে করা পরিমাপ:

| ফরম্যাট | বিট/ওজন | ওজনের SNR | BF16-এর সাপেক্ষে লজিট কোসাইন |
|---|---|---|---|
| BF16 | 16,00 | — | 1,0000 |
| INT8 | 8,19 | 44,6 dB | 0,9998 |
| NVFP4 | 4,50 | 20,4 dB | 0,9664 |
| INT4 | 4,16 | 20,0 dB | 0,9427 |
| INT4 + Hadamard | 4,16 | 21,0 dB | 0,9582 |

এই পরিমাপ থেকে পাওয়া দুটি পর্যবেক্ষণ ডিফল্ট বদলে দিয়েছে:

* **হ্যাডামার্ড ঘূর্ণন INT4-কে সাহায্য করে, NVFP4-কে নয়।** INT4-এর 128-এর
  গ্রুপ একটি বিচ্ছিন্ন বহির্মুখী চ্যানেল শুষে নিতে পারে না, তাই চরম মান
  ছড়িয়ে দেওয়া প্রতি সক্রিয়করণে একটি n log n রূপান্তরের যোগ্য। NVFP4-এর
  16-এর ব্লক আগে থেকেই নিজের স্কেল বহন করে। তাই `--hadamard auto`, যা এটি
  শুধু INT4-এ প্রয়োগ করে।
* **KV ক্যাশের জন্য INT8, FP8 E4M3-কে হারায়**, একই আকারে 44 dB বনাম 32 dB,
  কারণ প্রতি (টোকেন, হেড) একটি স্কেল আগে থেকেই সেই গতিশীল পরিসর দেয় যার
  জন্য FP8 সূচক বিট খরচ করে। তাই দুটি কার্ডই INT8-এ KV ক্যাশ ব্যবহার করে,
  যদিও 5090 FP8 পারত।
