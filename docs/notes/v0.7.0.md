# v0.7.0 — english / français

## English

**Decoding parity reached against NInfer, plus a night of compounding gains and two capacity/quality fixes.**

- **Decoding-step parity with NInfer** (piece 202): on Qwen3.8-27B-unsloth-mixte-i8c, b=8, host decode step
  16.09 ms vs 15.98 ms for NInfer — **+0.7 %, within parity**. The served chat benchmark still trails, 422.6 tok/s
  vs ≈463 for NInfer (**−8.7 %**): the gap sits in serving overhead (benchmark step vs raw step, 2.84 ms vs
  1.29 ms), not in the kernels — breakdown in progress (pieces 204/221).
- **+22.08 % throughput from one night's work** (piece 190, same alias, same batch, main vs main — not a
  comparison against another engine): 323.4 → 394.8 tok/s, made of six merged pieces — 172, 175/175b, 176, 179,
  182, 187.
- **Gains on top of that, now on by default**:
  - GDN α/β gates in a single call (`ACVRAM_GDN_AB=auto`, pieces 175/175b) — bit-exact against the two separate
    `F.linear` calls at every M, no KL criterion needed.
  - int8 GEMV activations processed in slices of 6 instead of 16 (piece 187), **+6.65 %** on the mixte b=8
    benchmark.
  - GDN β‖α on a second CUDA stream (piece 194 b2, `ACVRAM_GDN_AB_FLUX=1`), **+2.20 %** at b=8.
  - Narrow int8 GEMM spanning the full K width per channel (piece 195b, `ACVRAM_ETROIT_CANAL=1`), **+4.01 %** throughput,
    **−3.76 %** J/token at b=8.
- **KV capacity now correct for vision/MTP models** (piece 201): a model whose vision or multi-token-prediction
  head didn't fit used to load silently anyway; announced KV capacity is now lowered to account for it
  (Qwen3.8-nvfp4 **−7.4 %**, gemma-4-31B-vision **−21.4 %**). A transient int8 copy (i8c) is served without OOM,
  at no benchmark cost.
- **Per-expert-row Marlin factor: default reverted to 0** (piece 229, poste3 c40a952b1 — supersedes the piece
  209/226 decision below): a 3-arm bench on Qwen3-Coder-30B-A3B-nvfp4, b=8, sustained load — A 1750.0 · B
  (`PAR_LIGNE=1`) 1547.3 · C (`=0`) 1784.0 tok/s — B/C **−15.3 %** (held), A/C **+1.9 %** (held). Piece 209 alone
  carries the regression; contradicts piece 226's single-burst measurement. `ACVRAM_MARLIN_PAR_LIGNE=0` is now
  the default for 0.7.0 (decision, piece 232b poste6); `=1` stays available opt-in.
  - *(Superseded context, piece 209/226):* the −8.9 % tok/s regression first measured on this model (piece 217)
    turned out to be an artefact of that benchmark generating freely from randomly-sampled-token prompts — its
    degenerate outputs diverge between arms and route to different experts. With real prompts (the chat
    benchmark) and a single burst, the same model gained +12.8 % throughput and −18.4 % J/token at b=8 — this
    measurement held at burst but not under sustained load (see piece 229 above).
- **`/v1/completions` logprobs fix** (pieces 210/210b): logprobs for an empty-text token are now kept (tracked by
  `token_ids`, not `text_delta`); token usage is omitted from the stream when the client didn't ask for
  `stream_options.include_usage`, instead of a misleading all-zero `CompletionChunk`. The TTFT tool used to count
  these empty tokens as "no token received" — that was a tooling bug, not a serving one.
- **KV margin fix for recurrent-layer models** (piece 212): the VRAM headroom reserved before CUDA-graph capture
  now doubles for GDN/KDA/mamba2-style architectures (`_KV_MARGE_MIN_GDN` = 3072 MiB instead of 1536) — roughly
  **−12,192 KV tokens** of announced capacity on the affected Qwen3.8 variants, but no more silent OOM risk.

### Additional fixes
- **First decode batch now bit-exact with the following ones** (piece 213b, poste5 d57159556 + dd28d98dd): root
  cause was the RoPE cos/sin cache (`layers.py:674/721/863`) — the process's first prefill built its tables in
  unrounded fp32, later reconstructions in bf16, producing a first-batch drift. Fix: fixed dtype for the module
  plus `loader.py:313`. Calibration carried the same drift (`quant/collect.py:257`), fixed in piece 235 (poste2
  bbad9e189). Both enter 0.7.0.
- **`carte.sh` now kills the whole command's process group** (piece 244, poste3 5eb5e05a7): `setsid` + signal to
  the group, refuses to proceed if the group is still alive — closes a class of orphaned-process contamination
  between measurement sessions.
- **Packaging: AUR, RPM (COPR), Flathub, and Weblate**, released alongside GitHub: AUR depends on
  `python-pytorch-cuda` (piece 236a, poste3 749ef7e46); RPM/Fedora has no packaged CUDA torch, so a private venv
  is used instead (same piece); Flathub bundles `org.freedesktop.Platform.GL.nvidia` (≈1.9 GB, precompiled
  kernels required — piece 236b, poste6 e19ca029c; full Flatpak job, piece 241, poste6 772c8bf61); Weblate
  serves the interface strings, the README stays outside Weblate (piece 236c, poste2 fae740994).
- **`SECURITY.md` added** (main, 29a8ff944).
- **README rewritten** in the animematrix style (piece 231, poste3 f0b1e381f) with a `TRADUIRE.md` translation
  guide; translations delivered: de, es, it, pt, nl, ca, ro, da, sv, nb (piece 238, poste2) — other languages
  in progress.

### Known issue
A content-contamination bug (piece 213) — on some mixed models at b=8, a request's output could depend on the
request that immediately preceded it on the same engine — is root-caused and fixed by piece 213b above; no
open cross-request isolation issue is known at release time.

## Français

**Parité de décodage atteinte face à NInfer, une nuit de gains cumulés, et deux corrections de capacité/qualité.**

- **Parité du pas de décodage avec NInfer** (pièce 202) : sur Qwen3.8-27B-unsloth-mixte-i8c, b=8, pas hôte
  16,09 ms contre 15,98 ms chez NInfer — **+0,7 %, dans la parité**. Le banc chat servi reste derrière,
  422,6 t/s contre ≈463 chez NInfer (**−8,7 %**) : l'écart est dans le service (banc − pas, 2,84 ms contre
  1,29 ms), pas dans les noyaux — décomposition en cours (pièces 204/221).
- **+22,08 % de débit en une nuit** (pièce 190, même alias, même b, main contre main — pas une comparaison à un
  autre moteur) : 323,4 → 394,8 t/s, composé de six pièces fusionnées — 172, 175/175b, 176, 179, 182, 187.
- **Gains au-dessus, désormais au défaut** :
  - portes GDN α/β en un seul appel (`ACVRAM_GDN_AB=auto`, pièces 175/175b) — exact au bit contre les deux
    appels `F.linear` séparés, à chaque M, sans critère KL nécessaire.
  - activations du GEMV int8 traitées par tranches de 6 au lieu de 16 (pièce 187), **+6,65 %** sur le banc
    mixte b=8.
  - β‖α GDN sur un second flux CUDA (pièce 194 b2, `ACVRAM_GDN_AB_FLUX=1`), **+2,20 %** à b=8.
  - GEMM int8 étroit à K entier par canal (pièce 195b, `ACVRAM_ETROIT_CANAL=1`), **+4,01 %** de débit,
    **−3,76 %** de J/jeton à b=8.
- **Capacité KV désormais correcte pour les modèles vision/MTP** (pièce 201) : un modèle dont la tête vision ou
  de prédiction multi-jetons ne tenait pas se chargeait quand même, en silence ; la capacité KV annoncée baisse
  désormais pour en tenir compte (Qwen3.8-nvfp4 **−7,4 %**, gemma-4-31B-vision **−21,4 %**). Une copie int8
  transitoire (i8c) est servie sans OOM, sans coût au banc.
- **Facteur Marlin par ligne d'expert : défaut ramené à 0** (pièce 229, poste3 c40a952b1 — remplace la décision
  209/226 ci-dessous) : 3 bras sur Qwen3-Coder-30B-A3B-nvfp4, b=8, charge soutenue — A 1750,0 · B
  (`PAR_LIGNE=1`) 1547,3 · C (`=0`) 1784,0 t/s — B/C **−15,3 %** (TENU), A/C **+1,9 %** (TENU). La pièce 209
  seule porte la régression ; contredit la mesure en salve unique de la 226. `ACVRAM_MARLIN_PAR_LIGNE=0` devient
  le défaut pour 0.7.0 (décision, pièce 232b poste6) ; `=1` reste disponible en opt-in.
  - *(Contexte remplacé, pièce 209/226)* : la régression de −8,9 % t/s mesurée d'abord sur ce modèle (pièce 217)
    était un artefact de ce banc, qui génère librement depuis des invites à jetons tirés au hasard — ses sorties
    dégénérées divergent entre bras et routent vers d'autres experts. À invites réelles (banc chat) et en salve
    unique, le même modèle gagnait +12,8 % de débit et −18,4 % de J/jeton à b=8 — mesure tenue en salve, pas en
    charge soutenue (voir pièce 229 ci-dessus).
- **Correctif logprobs `/v1/completions`** (pièces 210/210b) : les logprobs d'un jeton à texte vide sont
  désormais gardés (suivi par `token_ids`, pas `text_delta`) ; l'usage des jetons est omis du flux quand le
  client n'a pas demandé `stream_options.include_usage`, au lieu d'un `CompletionChunk` trompeur à zéro partout.
  L'outil TTFT comptait ces jetons vides comme « aucun jeton reçu » — un bogue d'outillage, pas de service.
- **Correctif de marge KV pour les modèles à couche récurrente** (pièce 212) : la marge de VRAM réservée avant
  la capture des graphes CUDA double désormais pour les architectures GDN/KDA/mamba2 (`_KV_MARGE_MIN_GDN` =
  3 072 Mio au lieu de 1 536) — environ **−12 192 jetons** de capacité KV annoncée sur les Qwen3.8 concernés,
  mais plus de risque d'OOM silencieux.

### Correctifs supplémentaires
- **Le 1er lot de décodage égale désormais les suivants au bit** (pièce 213b, poste5 d57159556 + dd28d98dd) :
  cause trouvée dans le cache RoPE cos/sin (`layers.py:674/721/863`) — le 1er préfill du processus construisait
  ses tables en fp32 non arrondi, les reconstructions suivantes en bf16, d'où la dérive du premier lot.
  Correctif : dtype fixe du module + `loader.py:313`. La calibration portait la même dérive
  (`quant/collect.py:257`), corrigée par la pièce 235 (poste2 bbad9e189). Les deux entrent dans 0.7.0.
- **`carte.sh` tue désormais tout le groupe de processus de la commande** (pièce 244, poste3 5eb5e05a7) :
  `setsid` + signal au groupe, refuse de continuer si le groupe est encore vivant — ferme une classe de
  contamination par processus orphelins entre séances de mesure.
- **Paquets AUR, RPM (COPR), Flathub et Weblate**, joints à la release GitHub : AUR dépend de
  `python-pytorch-cuda` (pièce 236a, poste3 749ef7e46) ; RPM/Fedora n'a pas de torch CUDA empaqueté, un venv
  privé est utilisé à la place (même pièce) ; Flathub embarque `org.freedesktop.Platform.GL.nvidia` (≈1,9 Go,
  noyaux précompilés requis — pièce 236b, poste6 e19ca029c ; job Flatpak complet, pièce 241, poste6
  772c8bf61) ; Weblate sert les chaînes de l'interface, le README reste hors Weblate (pièce 236c, poste2
  fae740994).
- **`SECURITY.md` ajouté** (main, 29a8ff944).
- **README refait** dans le style animematrix (pièce 231, poste3 f0b1e381f) avec un guide `TRADUIRE.md` ;
  traductions livrées : de, es, it, pt, nl, ca, ro, da, sv, nb (pièce 238, poste2) — autres langues en cours.

### Défaut connu
Un bogue de contamination de contenu (pièce 213) — sur certains modèles mixtes à b=8, la sortie d'une requête
pouvait dépendre de la requête qui l'avait immédiatement précédée sur le même moteur — a sa cause établie et
son correctif livré par la pièce 213b ci-dessus ; aucun problème d'isolation entre requêtes n'est connu ouvert
à la sortie de cette version.
