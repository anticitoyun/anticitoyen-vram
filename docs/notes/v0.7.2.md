# v0.7.2 — english / français

## English

**Two `doctor`/packaging fixes: a silent failure on every host, and a wrongly-fatal optional extra.**

- **`acvram doctor` exited 1 everywhere, host and Flatpak** (piece 070b, poste6 77343eed0): `_doctor_eco`
  (piece "poste7-eco", 19/09) called `subprocess.run` without `cli.py` importing `subprocess` — a `NameError` on
  the very last line, after the full report had already printed, invisible to anyone reading only the
  "ok / ECHEC" lines. Caught by verif-070 (doctor inside the Flatpak sandbox, exit code 1 with 0 ECHEC on the
  host). Fix: `import subprocess`; test `tests/test_doctor_eco_070b.py` (fake sudo, red on the old code).
- **The `vision` extra (transformers, pillow) is a doctor ALERT, not a FAILURE, and the Flatpak bundles it**
  (piece 273, poste6 9e1de7ab9, decision by chef): 0.7.0's Flatpak doctor returned
  `ECHEC transformers est absent`, `ECHEC PIL est absent` — the `sources-pypi.py` list in `release.yml` did not
  include the extra, and the doctor required what `pyproject` declares optional (a 21/09 decision, gap P3, now
  reversed: a `.deb` or pip user without multimodal no longer sees a red doctor; a multimodal model without
  `vision` still fails at load time, in plain text). `_doctor_modules()`: required (safetensors, fastapi,
  uvicorn, tokenizers, jinja2) stays a FAILURE; extras (`vision`) become an
  `alerte vision indisponible (… absent) : pip install 'acvram[vision]'`, exit code 0. Flatpak: transformers
  and pillow added to the `sources-pypi.py` list (44 cp314/abi3/py3 wheels resolved offline in 18 s, no sdist).
  Tests: `tests/test_doctor_modules_273.py` (fake imports: without vision → 0 + alert, with → ok),
  `tests/test_flathub_vision_273.py`.

### Install / upgrade
```bash
git pull
./install.sh
```
