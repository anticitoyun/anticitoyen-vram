> Поддержать: [buymeacoffee.com/anticitoyen](https://buymeacoffee.com/anticitoyen)

Шлюз инференса, совместимый с API OpenAI, который рассматривает память как
иерархию и даёт каждому GPU тот числовой формат, который его кремний читает
лучше всего.

Создан для одной конкретной машины:

| | |
|---|---|
| Процессор | Intel Core i9-14900K (8 P-ядер + 16 E-ядер) |
| Материнская плата | ASUS ROG Maximus Z790 Dark Hero |
| Память | 96 ГБ DDR5 |
| GPU 0 | ASUS RTX 5090 Astral LC OC, 32 ГБ — Blackwell, `sm_120` |
| GPU 1 | ASUS RTX 3080 Ti, 12 ГБ — Ampere, `sm_86` |
| Система | Ubuntu 26.04 LTS (CUDA 13); обе карты в PCIe x8/x8, ограничены 400 Вт / 275 Вт |

## Две идеи

**Один формат на GPU.** У RTX 5090 есть тензорные ядра FP4; у RTX 3080 Ti их
нет, как нет и FP8. Привести обе к общему формату значило бы растратить 5090.
Поэтому конвертер записывает *одну и ту же модель дважды*, в том формате,
который каждое назначение действительно умеет использовать:

| | RTX 5090 | RTX 3080 Ti |
|---|---|---|
| веса | **NVFP4** — E2M1 + масштаб FP8 E4M3 на каждые 16 | **INT4** — uint4 + масштаб и ноль fp16 на каждые 128 |
| бит на вес | 4,50 | 4,16 |
| относительно BF16 | в 3,56 раза меньше | в 3,85 раза меньше |
| режим вычислений | тензорные ядра FP4 | деквантование в FP16 внутри ядра, тензорные ядра FP16 |
| KV-кэш | INT8 | INT8 |

32 ГБ VRAM при 4,5 бита на вес вмещают около **56 миллиардов параметров**
против 16 миллиардов в BF16. На двух картах это примерно **78 миллиардов
резидентных параметров** ещё до обращения к оперативной памяти.

**Память — это иерархия, а не стена.** Три уровня, и планировщик измеряет,
сколько стоит каждый, вместо того чтобы надеяться, что модель поместится:

```
RTX 5090     32 Go   ~1790 Go/s     NVFP4
RTX 3080 Ti  12 Go    ~912 Go/s     INT4
DDR5 hôte    96 Go   limité par le PCIe ou la DDR
```

## Быстрый старт

```bash
./install.sh                       # environnement virtuel + torch cu128 + acvram
acvram doctor                      # cette machine est-elle prête, et pour quoi
acvram detect                      # qu'y a-t-il réellement ici

acvram plan  ~/modeles/Qwen3-32B                    # où irait chaque couche
acvram convert ~/modeles/Qwen3-32B -o ~/acv/qwen3-32b
acvram serve ~/acv/qwen3-32b --port 8000
```

Затем подключается любой клиент OpenAI:

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-32b","messages":[{"role":"user","content":"Bonjour"}],"stream":true}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="inutilise")
client.chat.completions.create(model="qwen3-32b",
                               messages=[{"role": "user", "content": "Bonjour"}])
```

## Что говорит `acvram plan`

Планировщик стоит запустить до любой загрузки. Он отвечает на вопросы,
которые решают, пригодна ли модель для этой машины:

```
$ acvram plan ~/modeles/Llama-3.3-70B --max-model-len 32768 --max-seqs 4

  etage   format      capacite      poids         KV  tranche
  cuda:0  nvfp4        30,3 Gio   25,5 Gio   4,5 Gio  couches 0-58
  cuda:1  int4_awq     10,9 Gio    8,7 Gio   1,6 Gio  couches 59-79
  cpu     nvfp4        74,8 Gio    3,4 Gio       0 o  -

  poids au total     37,6 Gio
  lu par jeton       35,1 Gio
  KV par jeton       162,5 Kio  -> 39 843 jetons en cache
  MLP en RAM hote    55-58

  decodage estime    17,8 jetons/s  (lot de 1)
  prefill estime     847 jetons/s
```

Он исследует пространство конфигураций вместо того, чтобы взять первую
подходящую, и два его решения достаточно неочевидны, чтобы их проговорить:

* **Он оставляет 3080 Ti без работы**, когда модель помещается на одной
  5090. Части конвейера выполняются последовательно: добавить ступень на
  912 ГБ/с в конвейер на 1790 ГБ/с — значит замедлить декодирование одного
  потока. Принудительно: `--gpus all`.
* **Он сжимает KV-кэш, чтобы удержать веса в VRAM.** Каждый гигабайт,
  отданный кэшу, — это гигабайт весов, вытесненный на шину PCIe, а чтение
  веса через PCIe стоит примерно в тридцать раз дороже, чем из VRAM. На 70B
  выше один этот компромисс переводит с 2,3 на 17,8 токенов/с.

## Быстрее

Четыре оптимизации, каждая проверена доказательством эквивалентности, а не
только секундомером: оптимизация, меняющая ответ, — это ошибка.

### Спекулятивное декодирование (`--speculative`)

Декодировать один токен с батчем размера 1 — задача, ограниченная памятью:
машина читает все активные веса ради одного токена. Проверка K предложенных
токенов читает те же веса **один раз**. Два предлагающих:

* `ngram` (по умолчанию) — ищет текущий суффикс раньше в контексте и
  предлагает то, что за ним следовало. Ничего не стоит, не требует модели.
  Окупается, когда вывод копирует ввод: правка кода, RAG, резюме.
* `draft` — маленькая модель на втором устройстве. На этой сборке это
  RTX 3080 Ti, которую планировщик намеренно оставляет свободной для любой
  модели, помещающейся на 5090.

Принятие точное, а не приближённое: предложение принимается с вероятностью
`min(1, p/q)`, а отклонение пересэмплирует из нормированной положительной
части `p - q`. По 40 000 розыгрышам против намеренно плохо откалиброванного
черновика выданное распределение остаётся в пределах 0,002 полной вариации
от цели — спекуляция покупает скорость, но никогда не другой ответ.

```
modele jouet, glouton, k=4    etapes   jetons/etape   sortie
  sans speculation                23           1,00   reference
  n-grammes                       13           1,77   identique
  brouillon (= cible)              5           4,60   identique
```

### Кэш префиксов (включён по умолчанию)

Блоки адресуются *цепным* хешем своего среза токенов: два запроса с общей
системной инструкцией разделяют её блоки, и второму не нужно их
пересчитывать. Цепочка необходима: те же шестнадцать токенов в другом
контексте не содержат тех же ключей и значений, и хеш одного лишь среза
подсунул бы кэш одной последовательности другой.

Освобождённый блок, содержимое которого остаётся опознаваемым, попадает в
очередь LRU, а не в список свободных: так кэш переживает запросы, никогда
не отказывая в выделении, которое мог бы обслужить.

### Вычисления на уровне хоста (`--host-exec`)

Слой, веса которого лежат в RAM, можно скопировать на GPU или вычислить на
месте. Оба пути ограничены памятью и читают одни и те же байты: быстрее тот,
у кого шире шина — PCIe 5.0 x16 даёт около 54 ГБ/с, двухканальная DDR5 около
70 ГБ/с, — а вычисление на месте к тому же оставляет GPU свободным, вместо
того чтобы заставлять его ждать копию.

Это окупается, только если процессор читает 4-битные упакованные веса
напрямую. Отсюда маленькое ядро на C++ с путём AVX2 (`acvram_cpu.cpp`,
загружается через ctypes, без заголовков Python и без ninja). Даже на своей
**скалярной** запасной ветке оно обгоняет `dequantize() @ x` в 1,44 раза в
INT4 и в 3,21 раза в NVFP4, потому что последний сначала пишет 32-битную
копию всей матрицы.

На Mistral-Large-123B оценка планировщика растёт с 1,35 до 2,42 токена/с.

### Смешанная точность (`--snr-floor`, по умолчанию выключена)

Конвертер измеряет отношение сигнал/шум на выходе каждого слоя для каждого
тензора и может повысить до более широкого формата те, что опускаются ниже
`--snr-floor`, в пределах 15 % тензоров и ценового потолка
(`--promotion-cout-max`, в добавленных мебибайтах).

Порог **по умолчанию равен нулю**: ничего не повышается. Декодирование
ограничено пропускной способностью памяти, и измерение на
`Huihui-Qwen3.8-27B` решает — порог 25 дБ стоит 13,4 % памяти и 10,6 %
пропускной способности (18,50 ГиБ и 41,8 т/с против 16,02 и 46,2) ради 2,0 %
перплексии (42,591 против 43,447, корпус 16 383 токена). `--snr-floor 25`
возвращает прежнее поведение, когда качество важнее скорости.

### И `acvram eval`

Отношение сигнал/шум и косинус логитов — приближения.
`acvram eval КАТ [КАТ ...]` измеряет перплексию скользящим окном, чтобы выбор
формата решался на доказательствах:

```
$ acvram eval ~/acv/qwen3-32b-nvfp4 ~/acv/qwen3-32b-int4
  modele                   ppl     bpp      taille    jetons
  qwen3-32b-nvfp4        6,412    4,51    17,4 Gio      8192
  qwen3-32b-int4         6,583    4,17    16,1 Gio      8192  (+2,7 %)
```

## Точки входа HTTP

| точка входа | примечания |
|---|---|
| `POST /v1/chat/completions` | поток SSE или единый ответ; использует шаблон диалога модели |
| `POST /v1/completions` | промпт текстом или идентификаторами токенов |
| `POST /v1/embeddings` | усреднённые конечные скрытые состояния, L2-нормированные, `dimensions` учитывается |
| `GET /v1/models` | плюс блок `acvram`: форматы, устройства, ёмкость KV-кэша |
| `GET /health`, `GET /metrics` | скорость декодирования, занятость блоков KV |

Имена полей этих ответов остаются английскими: это протокол OpenAI, и их
перевод сломал бы всех существующих клиентов.

## Откуда взяты числа

Каждое значение выше получено кодом этого репозитория и проверено `pytest`.
Измерения на процессоре с эталонными ядрами:

| формат | бит/вес | SNR весов | косинус логитов vs BF16 |
|---|---|---|---|
| BF16 | 16,00 | — | 1,0000 |
| INT8 | 8,19 | 44,6 дБ | 0,9998 |
| NVFP4 | 4,50 | 20,4 дБ | 0,9664 |
| INT4 | 4,16 | 20,0 дБ | 0,9427 |
| INT4 + Hadamard | 4,16 | 21,0 дБ | 0,9582 |

Два вывода из этих измерений изменили значения по умолчанию:

* **Поворот Адамара помогает INT4, но не NVFP4.** Группы по 128 в INT4 не
  могут поглотить одиночный выбросный канал, поэтому размазать крайние
  значения стоит преобразования n log n на активацию. Блоки по 16 в NVFP4
  уже несут собственный масштаб. Отсюда `--hadamard auto`, применяющий его
  только к INT4.
* **INT8 обходит FP8 E4M3 для KV-кэша**: 44 дБ против 32 дБ при одинаковом
  размере, потому что масштаб на (токен, голову) уже даёт тот динамический
  диапазон, на который FP8 тратит биты экспоненты. Поэтому обе карты
  используют KV-кэш в INT8, хотя 5090 умеет FP8.

## Измеренные результаты (22.09.2026, RTX 5090 при 400 Вт, режим ≥ 20 с по счётчику энергии)

Qwen3-Coder-30B-A3B в NVFP4 (эксперты) + INT8 (внимание, голова), один
протокол для всех движков (`outils/`, одна карта, `energie.py`):

| | acvram 0.6.35 | vLLM 0.29 (CUTLASS FP4) | llama.cpp (sm_120) |
|---|---|---|---|
| декодирование, 12 последовательностей | **1 625,5 т/с** | 1 596,1 т/с | — |
| декодирование, 1 последовательность | **380,8 т/с** | 290,6 т/с | 323,6 т/с |
| prefill pp2048 | **22 707** токенов/с | 21 054 | 8 671 (TabbyAPI, отозвано) |

Пропускная способность на сегодня (стенд 1030, эко-режим `-lgc 2700`, конвейер в работе; жадная выборка захвачена в графе CUDA, по умолчанию с 0.6.35). b=12 — официальная запечатанная ячейка (медиана 6 чередующихся окон, частота по окну). Значение vLLM 1 596,1 — замороженный эталон от 21.09 (vLLM в этот день не перезапускался): разрыв +1,84 % считается при равном эталоне, а не как перемер обоих в одно утро. Дж/токен при равной частоте против трёх движков остаётся в перемере (`outils/gpu/mesure/banc-4moteurs.py`) — число без режима не публикуется.

Утром 14.09 acvram показывал в той же ячейке 630 т/с и 0,619 Дж/токен: выигрыш
дали нативный FP4 MMA Blackwell (`mma.sync … kind::mxf4nvf4`, ×7,9 к bf16),
MoE как сгруппированный GEMM по корзине батча, маршрутизация одним ядром
(3 677 → 1 517 запусков за шаг) и узкий GEMM на тензорных ядрах для проекций.
У каждого числа есть заметка в `acvram-memoire/revue/` с прогнозом,
запечатанным до измерения, инструментом и его режимом — число без режима не
публикуется.

Где acvram впереди: модели MLA (GLM-4.7-Flash) в нативном NVFP4 sm_120
(b=1: 165,35 т/с в работе), которые vLLM обслуживает только в FP8; модели,
не помещающиеся в VRAM; и, начиная с 0.6.35, декодирование большим батчем MoE,
помещающегося в VRAM — b=12 вырос с 1 540 (0.6.34) до 1 625,5 т/с, то есть
+1,84 % впереди замороженного эталона vLLM (1 596,1). Разрыв остаётся узким и
при замороженном эталоне; разрыв по энергии ещё предстоит перемерить.

## Состояние

Версия 0.6.35. Всё работает на 5090: ядра CUDA, собранные для `sm_120a`
(нативный FP4) и `sm_86`, графы CUDA, квантование NVFP4/INT8/INT4,
HTTP-сервер. Ограждения на месте: карта невидима для рабочих сессий
(`CUDA_VISIBLE_DEVICES` пуст), и только `outils/carte.sh` выдаёт её под
блокировкой одному измерению за раз; сторож журналирует любой доступ вне
блокировки; измерение энергии, охватывающее больше одной карты или меньше
10 с, признаётся недействительным; модель, загруженная в деградированном
режиме, сообщает об этом и не участвует в дуэли.

640 тестов (`pytest -q`, минута на процессоре; GPU-тесты выполняются только
под `carte.sh`). Учёт работы: `acvram-memoire/` (правила, справочник,
тетради, ревью из 180 заметок).
