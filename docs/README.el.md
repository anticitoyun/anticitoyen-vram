## Οι δύο ιδέες

Σχεδιασμένο για ένα συγκεκριμένο μηχάνημα:

| | |
|---|---|
| Επεξεργαστής | Intel Core i9-14900K (8 πυρήνες P + 16 πυρήνες E) |
| Μητρική | ASUS ROG Maximus Z790 Dark Hero |
| Μνήμη | 96 Go DDR5 |
| GPU 0 | ASUS RTX 5090 Astral LC OC, 32 Go — Blackwell, `sm_120` |
| GPU 1 | ASUS RTX 3080 Ti, 12 Go — Ampere, `sm_86` |
| Σύστημα | Ubuntu 26.04 LTS (CUDA 13) · οι δύο κάρτες σε PCIe x8/x8, περιορισμένες στα 400 W / 275 W |

**Μία μορφή ανά GPU.** Η RTX 5090 διαθέτει tensor cores FP4· η RTX 3080 Ti δεν διαθέτει, ούτε FP8. Η ευθυγράμμιση και των δύο σε κοινή μορφή θα σπαταλούσε τη 5090. Ο μετατροπέας γράφει λοιπόν *το ίδιο μοντέλο δύο φορές*, στη μορφή που κάθε προορισμός μπορεί πραγματικά να αξιοποιήσει:

| | RTX 5090 | RTX 3080 Ti |
|---|---|---|
| βάρη | **NVFP4** — E2M1 + κλίμακα FP8 E4M3 κάθε 16 | **INT4** — uint4 + κλίμακα και μηδέν fp16 κάθε 128 |
| bits ανά βάρος | 4,50 | 4,16 |
| έναντι BF16 | ×3,56 μικρότερο | ×3,85 μικρότερο |
| τρόπος υπολογισμού | tensor cores FP4 | αποκβαντισμένο σε FP16 μέσα στον πυρήνα, tensor cores FP16 |
| cache KV | INT8 | INT8 |

32 Go VRAM στα 4,5 bits ανά βάρος χωρούν περίπου **56 δισεκατομμύρια παραμέτρους**, έναντι 16 δισεκατομμυρίων σε BF16. Και στις δύο κάρτες μαζί, αυτό δίνει περίπου **78 δισεκατομμύρια κατοικημένες παραμέτρους** πριν καν αγγίξουμε τη μνήμη RAM.

**Η μνήμη είναι ιεραρχία, όχι τείχος.** Τρία επίπεδα, και ο προγραμματιστής μετρά το κόστος καθενός αντί να ελπίζει ότι το μοντέλο θα χωρέσει:

```
RTX 5090     32 Go   ~1790 Go/s     NVFP4
RTX 3080 Ti  12 Go    ~912 Go/s     INT4
DDR5 hôte    96 Go   περιορισμένο από το PCIe ή τη DDR
```

## Γρήγορη εκκίνηση

```bash
./install.sh                       # εικονικό περιβάλλον + torch cu128 + acvram
acvram doctor                      # είναι αυτό το μηχάνημα έτοιμο, και για τι
acvram detect                      # τι υπάρχει πραγματικά εδώ

acvram plan  ~/modeles/Qwen3-32B                    # πού θα πήγαινε κάθε επίπεδο
acvram convert ~/modeles/Qwen3-32B -o ~/acv/qwen3-32b
acvram serve ~/acv/qwen3-32b --port 8000
```

Οποιοσδήποτε πελάτης OpenAI συνδέεται κατόπιν:

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-32b","messages":[{"role":"user","content":"Γεια σου"}],"stream":true}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="inutilise")
client.chat.completions.create(model="qwen3-32b",
                               messages=[{"role": "user", "content": "Γεια σου"}])
```

## Εγκατάσταση

Από την πηγή (όλες οι πλατφόρμες):

```bash
git clone https://github.com/anticitoyun/anticitoyen-vram.git && cd anticitoyen-vram
./install.sh
```

Ή μέσω πακέτου, ένα αρχείο συνημμένο σε κάθε [έκδοση GitHub](https://github.com/anticitoyun/anticitoyen-vram/releases/latest):

| Κανάλι | Αρχείο συνημμένο στην έκδοση | Εντολή |
|---|---|---|
| Debian / Ubuntu (.deb) | `acvram_<version>_amd64.deb` | `sudo dpkg -i acvram_<version>_amd64.deb` |
| Arch (AUR) | `aur-<version>.tar.gz` (PKGBUILD + .SRCINFO) | `tar xzf aur-<version>.tar.gz && cd acvram && makepkg -si` |
| Fedora / COPR (RPM) | `.rpm` / `.src.rpm` (ονόματα που παράγονται από το `rpmbuild`, όχι σταθερά) | `sudo rpm -i acvram-<version>-1.*.noarch.rpm` (ή `rpmbuild --rebuild *.src.rpm` από το `.src.rpm`) |
| Flatpak | `acvram-<version>.flatpak` | `flatpak install acvram-<version>.flatpak` |

Το Pip δεν δημοσιεύεται ως πακέτο (καμία χτισμένη wheel): το `pip install -e '.[dev]'` εγκαθιστά από κλώνο της πηγής, όπως το `./install.sh`.

<a id="plan"></a>

## Τι λέει η `acvram plan`

Ο προγραμματιστής αξίζει να τρέξει πριν από κάθε λήψη. Απαντά στα ερωτήματα που κρίνουν αν ένα μοντέλο είναι χρησιμοποιήσιμο σε αυτό το μηχάνημα:

```
$ acvram plan ~/modeles/Llama-3.3-70B --max-model-len 32768 --max-seqs 4

  etage   format      capacite      poids         KV  tranche
  cuda:0  nvfp4        30,3 Gio   25,5 Gio   4,5 Gio  couches 0-58
  cuda:1  int4_awq     10,9 Gio    8,7 Gio   1,6 Gio  couches 59-79
  cpu     nvfp4        74,8 Gio    3,4 Gio       0 o  -

  poids au total     37,6 Gio
  lu par jeton       35,1 Gio
  KV par jeton       162,5 Kio  -> 39 843 jetons en cache
  MLP en RAM hote    55-58

  decodage estime    17,8 jetons/s  (lot de 1)
  prefill estime     847 jetons/s
```

Εξερευνά τον χώρο των διαμορφώσεων αντί να κρατά την πρώτη που χωράει, και δύο από τις αποφάσεις του αξίζει να ειπωθούν, καθώς είναι αρκετά αντι-διαισθητικές:

* **Αφήνει τη 3080 Ti αχρησιμοποίητη** όταν ένα μοντέλο χωράει μόνο στη 5090. Τα τμήματα ενός pipeline εκτελούνται σειριακά: η προσθήκη ενός σταδίου στα 912 Go/s μέσα σε ένα pipeline στα 1790 Go/s επιβραδύνει την αποκωδικοποίηση μονής ροής. Επιβάλλεται με `--gpus all`.
* **Συρρικνώνει το cache KV για να κρατήσει τα βάρη στη VRAM.** Κάθε gibibyte που δίνεται στο cache είναι ένα gibibyte βαρών που απωθείται στο δίαυλο PCIe, και η ανάγνωση ενός βάρους μέσω PCIe κοστίζει περίπου τριάντα φορές όσο από τη VRAM. Στο 70B παραπάνω, μόνο αυτή η επιλογή ανεβάζει από 2,3 σε 17,8 tokens/s.

<a id="optimisations"></a>

## Πηγαίνοντας γρήγορα

Τέσσερις βελτιστοποιήσεις, καθεμία επαληθευμένη με απόδειξη ισοδυναμίας και όχι μόνο με χρονόμετρο: μια βελτιστοποίηση που αλλάζει την απάντηση είναι σφάλμα.

Τα γραμμικά NVFP4 των πυκνών μοντέλων περνούν εξ ορισμού από τη διάταξη Marlin (+57 έως +90 % ρυθμού στο b = 8, TTFT +2 έως +4 ms κατά το revue/poste6-piece147-verdict-24-09.md· εναλλακτική `ACVRAM_PROJ_MARLIN=0`, δείτε [CHANGELOG.md](../CHANGELOG.md)).

### Κερδοσκοπική αποκωδικοποίηση (`--speculative`)

Η αποκωδικοποίηση ενός token με batch μεγέθους 1 περιορίζεται από τη μνήμη: το μηχάνημα διαβάζει όλα τα ενεργά βάρη για να παράξει ένα μόνο token. Η επαλήθευση K προτεινόμενων tokens διαβάζει τα ίδια βάρη **μία μόνο φορά**. Δύο προτείνοντες:

* `ngram` (εξ ορισμού) — αναζητά το τρέχον επίθημα νωρίτερα στο πλαίσιο και προτείνει ό,τι ακολουθούσε. Δεν κοστίζει τίποτα, δεν απαιτεί κανένα μοντέλο. Αποδοτικό όταν η έξοδος αντιγράφει την είσοδο: επεξεργασία κώδικα, RAG, περίληψη.
* `draft` — ένα μικρό μοντέλο σε δεύτερη συσκευή. Σε αυτό το rig, αυτή η συσκευή είναι η RTX 3080 Ti, την οποία ο προγραμματιστής αφήνει σκόπιμα αδρανή για κάθε μοντέλο που χωράει στη 5090.

Το `mtp` (κεφαλή `nextn` του μοντέλου) και το `auto` υπάρχουν επίσης· μη αποδοτικά προς το παρόν και όχι ενεργά εξ ορισμού — δείτε `docs/ARCHITECTURE.md`.

Η αποδοχή είναι ακριβής, όχι κατά προσέγγιση: μια πρόταση γίνεται δεκτή με πιθανότητα `min(1, p/q)` και μια απόρριψη επαναδειγματοληπτεί στο κανονικοποιημένο θετικό τμήμα του `p - q`. Μετρημένο σε 40 000 δείγματα έναντι ενός σκόπιμα κακά βαθμονομημένου σχεδίου, η εκπεμπόμενη κατανομή παραμένει στα 0,002 συνολικής απόκλισης από τον στόχο — η κερδοσκοπία αγοράζει ταχύτητα, ποτέ διαφορετική απάντηση.

```
modele jouet, glouton, k=4    etapes   jetons/etape   sortie
  sans speculation                23           1,00   reference
  n-grammes                       13           1,77   identique
  brouillon (= cible)              5           4,60   identique
```

### Cache προθέματος (ενεργό εξ ορισμού)

Τα blocks διευθυνσιοδοτούνται από το *αλυσιδωτό* hash του τμήματος tokens τους: δύο αιτήματα που μοιράζονται μια εντολή συστήματος μοιράζονται τα blocks της, και το δεύτερο δεν χρειάζεται πλέον να τα προϋπολογίσει. Η αλυσίδωση είναι απαραίτητη: τα ίδια δεκαέξι tokens σε διαφορετικό πλαίσιο δεν περιέχουν τα ίδια κλειδιά και τιμές, και το hashing μόνο του τμήματος θα εξυπηρετούσε το cache μιας ακολουθίας σε μια άλλη.

Ένα απελευθερωμένο block του οποίου το περιεχόμενο παραμένει αναγνωρίσιμο εντάσσεται σε ουρά LRU αντί στη λίστα ελεύθερων blocks: το cache επιβιώνει έτσι μεταξύ αιτημάτων χωρίς ποτέ να αρνηθεί μια εκχώρηση που θα μπορούσε να είχε εξυπηρετήσει.

### Υπολογισμός επιπέδου host (`--host-exec`)

Ένα επίπεδο του οποίου τα βάρη κατοικούν στη RAM μπορεί να αντιγραφεί στο GPU ή να υπολογιστεί επί τόπου. Και οι δύο δρόμοι περιορίζονται από τη μνήμη και διαβάζουν τα ίδια bytes: ο ταχύτερος είναι αυτός με τον πλατύτερο δίαυλο — το PCIe 5.0 x16 δίνει περίπου 54 Go/s, η DDR5 σε διπλό κανάλι περίπου 70 Go/s — και ο επιτόπιος υπολογισμός επιπλέον αφήνει το GPU ελεύθερο αντί να το κάνει να περιμένει ένα αντίγραφο.

Αυτό αξίζει μόνο αν ο επεξεργαστής διαβάζει απευθείας τα βάρη συσκευασμένα σε 4 bits. Εξ ου και ένας μικρός πυρήνας C++ με διαδρομή AVX2 (`acvram_cpu.cpp`, φορτωμένος με ctypes, χωρίς Python headers ούτε ninja). Ακόμη και στον **βαθμωτό** εναλλακτικό κλάδο του, νικά το `dequantize() @ x` κατά παράγοντα 1,44 σε INT4 και 3,21 σε NVFP4, επειδή το δεύτερο γράφει πρώτα ένα αντίγραφο 32 bits ολόκληρου του πίνακα.

Στο Mistral-Large-123B, η εκτίμηση του προγραμματιστή ανεβαίνει από 1,35 σε 2,42 tokens/s.

### Μεικτή ακρίβεια (`--snr-floor`, απενεργοποιημένη εξ ορισμού)

Ο μετατροπέας μετρά τον λόγο σήματος προς θόρυβο στην έξοδο κάθε επιπέδου ανά τανυστή και μπορεί να προάγει σε ευρύτερη μορφή όσους πέφτουν κάτω από το `--snr-floor`, με όριο το 15 % των τανυστών και ανώτατο κόστος (`--promotion-cout-max`, σε mebibytes που προστίθενται).

Το κατώφλι είναι **μηδέν εξ ορισμού**: τίποτα δεν προάγεται. Η αποκωδικοποίηση περιορίζεται από το εύρος ζώνης μνήμης, και η μέτρηση στο `Huihui-Qwen3.8-27B` κρίνει — ένα κατώφλι 25 dB κοστίζει 13,4 % μνήμης και 10,6 % ρυθμού (18,50 Gio και 41,8 t/s έναντι 16,02 και 46,2) για 2,0 % περιπλοκότητας (42,591 έναντι 43,447, σώμα κειμένου 16 383 tokens). Το `--snr-floor 25` επαναφέρει την παλιά συμπεριφορά όταν η ποιότητα προηγείται της ταχύτητας.

### Και το `acvram eval`

Ο λόγος σήματος προς θόρυβο και το συνημίτονο των logits είναι προσεγγίσεις. Το `acvram eval REP [REP ...]` μετρά την περιπλοκότητα με κυλιόμενο παράθυρο, ώστε μια επιλογή μορφής να κρίνεται με αποδείξεις:

```
$ acvram eval ~/acv/qwen3-32b-nvfp4 ~/acv/qwen3-32b-int4
  modele                   ppl     bpp      taille    jetons
  qwen3-32b-nvfp4        6,412    4,51    17,4 Gio      8192
  qwen3-32b-int4         6,583    4,17    16,1 Gio      8192  (+2,7 %)
```

## Σημεία εισόδου HTTP

| σημείο εισόδου | σημειώσεις |
|---|---|
| `POST /v1/chat/completions` | ροή SSE ή μοναδική απάντηση· χρησιμοποιεί το πρότυπο συνομιλίας του μοντέλου |

## Από πού προέρχονται οι αριθμοί

Κάθε αναφερόμενη τιμή παραπάνω παράγεται από κώδικα αυτού του αποθετηρίου και επαληθεύεται με `pytest`. Μετρήσεις σε επεξεργαστή με τους πυρήνες αναφοράς:

| μορφή | bits/βάρος | SNR βαρών | συνημίτονο logits έναντι BF16 |
|---|---|---|---|
| BF16 | 16,00 | — | 1,0000 |
| INT8 | 8,19 | 44,6 dB | 0,9998 |
| NVFP4 | 4,50 | 20,4 dB | 0,9664 |
| INT4 | 4,16 | 20,0 dB | 0,9427 |
| INT4 + Hadamard | 4,16 | 21,0 dB | 0,9582 |

Δύο διαπιστώσεις από αυτές τις μετρήσεις άλλαξαν τις προεπιλεγμένες τιμές:

* **Μια περιστροφή Hadamard βοηθά το INT4 και όχι το NVFP4.** Οι ομάδες των 128 του INT4 δεν μπορούν να απορροφήσουν μια απομονωμένη ακραία τιμή καναλιού, οπότε η διασπορά των ακραίων τιμών αξίζει έναν μετασχηματισμό n log n ανά ενεργοποίηση. Τα blocks των 16 του NVFP4 φέρουν ήδη τη δική τους κλίμακα. Εξ ου και `--hadamard auto`, που το εφαρμόζει μόνο στο INT4.
* **Το INT8 νικά το FP8 E4M3 για το cache KV**, 44 dB έναντι 32 dB στο ίδιο μέγεθος, επειδή μια κλίμακα ανά (token, κεφαλή) παρέχει ήδη το δυναμικό εύρος για το οποίο το FP8 ξοδεύει bits εκθέτη. Και οι δύο κάρτες χρησιμοποιούν λοιπόν cache KV σε INT8, ακόμη κι αν η 5090 θα μπορούσε να κάνει FP8. Μια μορφή `k8v4` (τιμές σε INT4, −22 % bytes cache) υπάρχει προαιρετικά, **μη πιστοποιημένη** — δείτε `docs/ARCHITECTURE.md`.

## Κατάσταση

Έκδοση 0.6.38. Όλα τρέχουν στη 5090: πυρήνες CUDA μεταγλωττισμένοι για `sm_120a` (native FP4) και `sm_86`, γραφήματα CUDA, κβαντισμός NVFP4/INT8/INT4, εξυπηρετητής HTTP. Προστατευτικά σε ισχύ: η κάρτα είναι αόρατη στις συνεδρίες εργασίας (`CUDA_VISIBLE_DEVICES` κενό) και μόνο το `outils/carte.sh` τη διαθέτει, υπό κλείδωμα, σε μία μέτρηση τη φορά· ένας παρατηρητής καταγράφει κάθε πρόσβαση εκτός κλειδώματος· μια μέτρηση ενέργειας που καλύπτει περισσότερες από μία κάρτα ή λιγότερο από 10 s ακυρώνεται· ένα μοντέλο φορτωμένο σε υποβαθμισμένο καθεστώς το δηλώνει και δεν εισέρχεται σε μονομαχία.

4 107 δοκιμές (`pytest --collect-only -q`, ένα λεπτό σε επεξεργαστή· οι δοκιμές GPU τρέχουν μόνο υπό το `carte.sh`). Παρακολούθηση της εργασίας: `acvram-memoire/` (κανόνες, κατάλογος, ημερολόγια, ανασκόπηση αρκετών εκατοντάδων σημειώσεων).
