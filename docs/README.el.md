> Υποστήριξη: [buymeacoffee.com/anticitoyen](https://buymeacoffee.com/anticitoyen)

Μια πύλη συμπερασμού συμβατή με το API της OpenAI, που αντιμετωπίζει τη
μνήμη ως ιεραρχία και δίνει σε κάθε GPU την αριθμητική μορφή που το πυρίτιό
της διαβάζει καλύτερα.

Σχεδιασμένη για μια συγκεκριμένη μηχανή:

| | |
|---|---|
| Επεξεργαστής | Intel Core i9-14900K (8 πυρήνες P + 16 πυρήνες E) |
| Μητρική | ASUS ROG Maximus Z790 Dark Hero |
| Μνήμη | 96 GB DDR5 |
| GPU 0 | ASUS RTX 5090 Astral LC OC, 32 GB — Blackwell, `sm_120` |
| GPU 1 | ASUS RTX 3080 Ti, 12 GB — Ampere, `sm_86` |
| Σύστημα | Ubuntu 26.04 LTS (CUDA 13)· και οι δύο κάρτες σε PCIe x8/x8, περιορισμένες στα 400 W / 275 W |

## Οι δύο ιδέες

**Μία μορφή ανά GPU.** Η RTX 5090 διαθέτει tensor cores FP4· η RTX 3080 Ti
δεν έχει, ούτε FP8. Το να ευθυγραμμιστούν σε κοινή μορφή θα σπαταλούσε την
5090. Ο μετατροπέας γράφει λοιπόν *δύο φορές το ίδιο μοντέλο*, στη μορφή που
κάθε προορισμός μπορεί πραγματικά να εκμεταλλευτεί:

| | RTX 5090 | RTX 3080 Ti |
|---|---|---|
| βάρη | **NVFP4** — E2M1 + κλίμακα FP8 E4M3 ανά 16 | **INT4** — uint4 + κλίμακα και μηδέν fp16 ανά 128 |
| bit ανά βάρος | 4,50 | 4,16 |
| έναντι BF16 | ×3,56 μικρότερο | ×3,85 μικρότερο |
| τρόπος υπολογισμού | tensor cores FP4 | αποκβαντισμός σε FP16 μέσα στον πυρήνα, tensor cores FP16 |
| κρυφή μνήμη KV | INT8 | INT8 |

32 GB VRAM με 4,5 bit ανά βάρος χωρούν περίπου **56 δισεκατομμύρια
παραμέτρους**, έναντι 16 δισεκατομμυρίων σε BF16. Στις δύο κάρτες, αυτό κάνει
περίπου **78 δισεκατομμύρια μόνιμες παραμέτρους** πριν καν αγγίξουμε τη RAM.

**Η μνήμη είναι ιεραρχία, όχι τείχος.** Τρία επίπεδα, και ο σχεδιαστής μετρά
τι κοστίζει το καθένα αντί να ελπίζει ότι το μοντέλο θα χωρέσει:

```
RTX 5090     32 Go   ~1790 Go/s     NVFP4
RTX 3080 Ti  12 Go    ~912 Go/s     INT4
DDR5 hôte    96 Go   limité par le PCIe ou la DDR
```

## Γρήγορη εκκίνηση

```bash
./install.sh                       # environnement virtuel + torch cu128 + acvram
acvram doctor                      # cette machine est-elle prête, et pour quoi
acvram detect                      # qu'y a-t-il réellement ici

acvram plan  ~/modeles/Qwen3-32B                    # où irait chaque couche
acvram convert ~/modeles/Qwen3-32B -o ~/acv/qwen3-32b
acvram serve ~/acv/qwen3-32b --port 8000
```

Οποιοσδήποτε πελάτης OpenAI συνδέεται έπειτα:

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-32b","messages":[{"role":"user","content":"Bonjour"}],"stream":true}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="inutilise")
client.chat.completions.create(model="qwen3-32b",
                               messages=[{"role": "user", "content": "Bonjour"}])
```

## Τι λέει το `acvram plan`

Ο σχεδιαστής αξίζει να τρέξει πριν από κάθε λήψη. Απαντά στα ερωτήματα που
κρίνουν αν ένα μοντέλο είναι χρησιμοποιήσιμο σε αυτή τη μηχανή:

```
$ acvram plan ~/modeles/Llama-3.3-70B --max-model-len 32768 --max-seqs 4

  etage   format      capacite      poids         KV  tranche
  cuda:0  nvfp4        30,3 Gio   25,5 Gio   4,5 Gio  couches 0-58
  cuda:1  int4_awq     10,9 Gio    8,7 Gio   1,6 Gio  couches 59-79
  cpu     nvfp4        74,8 Gio    3,4 Gio       0 o  -

  poids au total     37,6 Gio
  lu par jeton       35,1 Gio
  KV par jeton       162,5 Kio  -> 39 843 jetons en cache
  MLP en RAM hote    55-58

  decodage estime    17,8 jetons/s  (lot de 1)
  prefill estime     847 jetons/s
```

Εξερευνά τον χώρο των διαμορφώσεων αντί να κρατά την πρώτη που χωρά, και
δύο από τις αποφάσεις του είναι αρκετά αντιδιαισθητικές ώστε να αξίζουν
διατύπωση:

* **Αφήνει την 3080 Ti αχρησιμοποίητη** όταν ένα μοντέλο χωρά στην 5090
  μόνη. Τα τμήματα μιας διοχέτευσης εκτελούνται σειριακά: το να προστεθεί ένα
  στάδιο 912 GB/s σε διοχέτευση 1790 GB/s επιβραδύνει την αποκωδικοποίηση
  μονής ροής. Εξαναγκάζεται με `--gpus all`.
* **Συρρικνώνει την κρυφή μνήμη KV για να κρατήσει τα βάρη στη VRAM.** Κάθε
  gigabyte που δίνεται στην κρυφή μνήμη είναι ένα gigabyte βαρών που ωθείται
  στον δίαυλο PCIe, και η ανάγνωση ενός βάρους μέσω PCIe κοστίζει περίπου
  τριάντα φορές όσο από τη VRAM. Στο 70B παραπάνω, αυτή η επιλογή και μόνο
  μεταφέρει από 2,3 σε 17,8 tokens/s.

## Ταχύτητα

Τέσσερις βελτιστοποιήσεις, καθεμία επαληθευμένη με απόδειξη ισοδυναμίας και
όχι μόνο με χρονόμετρο: μια βελτιστοποίηση που αλλάζει την απάντηση είναι
σφάλμα.

### Θεωρητική αποκωδικοποίηση (`--speculative`)

Η αποκωδικοποίηση ενός token με παρτίδα μεγέθους 1 περιορίζεται από τη
μνήμη: η μηχανή διαβάζει όλα τα ενεργά βάρη για να παραγάγει ένα μόνο token.
Η επαλήθευση K προτεινόμενων tokens διαβάζει τα ίδια βάρη **μία μόνο φορά**.
Δύο προτείνοντες:

* `ngram` (προεπιλογή) — αναζητά το τρέχον επίθημα νωρίτερα στο συγκείμενο
  και προτείνει ό,τι ακολουθούσε. Δεν κοστίζει τίποτα, δεν χρειάζεται
  μοντέλο. Αποδίδει όταν η έξοδος αντιγράφει την είσοδο: επεξεργασία κώδικα,
  RAG, περίληψη.
* `draft` — ένα μικρό μοντέλο σε δεύτερη συσκευή. Σε αυτό το σύστημα η
  συσκευή είναι η RTX 3080 Ti, την οποία ο σχεδιαστής αφήνει σκόπιμα αδρανή
  για κάθε μοντέλο που χωρά στην 5090.

Η αποδοχή είναι ακριβής, όχι προσεγγιστική: μια πρόταση γίνεται δεκτή με
πιθανότητα `min(1, p/q)` και μια απόρριψη επαναδειγματοληπτεί από το
κανονικοποιημένο θετικό μέρος του `p - q`. Μετρημένη σε 40 000 κληρώσεις
έναντι ενός σκόπιμα κακώς βαθμονομημένου προσχεδίου, η εκπεμπόμενη κατανομή
μένει σε 0,002 ολικής μεταβολής από τον στόχο — η θεωρητική αποκωδικοποίηση
αγοράζει ταχύτητα, ποτέ διαφορετική απάντηση.

```
modele jouet, glouton, k=4    etapes   jetons/etape   sortie
  sans speculation                23           1,00   reference
  n-grammes                       13           1,77   identique
  brouillon (= cible)              5           4,60   identique
```

### Κρυφή μνήμη προθέματος (ενεργή εξ ορισμού)

Τα μπλοκ διευθυνσιοδοτούνται με το *αλυσιδωτό* hash του τμήματος tokens τους:
δύο αιτήματα που μοιράζονται μια οδηγία συστήματος μοιράζονται τα μπλοκ της,
και το δεύτερο δεν χρειάζεται πια να τα προϋπολογίσει. Η αλυσίδωση είναι
απαραίτητη: τα ίδια δεκαέξι tokens σε διαφορετικό συγκείμενο δεν περιέχουν
τα ίδια κλειδιά και τιμές, και το hash μόνο του τμήματος θα σέρβιρε την
κρυφή μνήμη μιας ακολουθίας σε άλλη.

Ένα απελευθερωμένο μπλοκ με ακόμη αναγνωρίσιμο περιεχόμενο μπαίνει σε ουρά
LRU αντί στη λίστα ελεύθερων μπλοκ: έτσι η κρυφή μνήμη επιβιώνει μεταξύ
αιτημάτων χωρίς ποτέ να αρνηθεί μια δέσμευση που θα μπορούσε να εξυπηρετήσει.

### Υπολογισμός στο επίπεδο του ξενιστή (`--host-exec`)

Ένα στρώμα του οποίου τα βάρη βρίσκονται στη RAM μπορεί να αντιγραφεί στη
GPU ή να υπολογιστεί επί τόπου. Και οι δύο δρόμοι περιορίζονται από τη μνήμη
και διαβάζουν τα ίδια bytes: ταχύτερος είναι εκείνος με τον ευρύτερο δίαυλο —
το PCIe 5.0 x16 δίνει περίπου 54 GB/s, η DDR5 σε διπλό κανάλι περίπου
70 GB/s — και ο επί τόπου υπολογισμός αφήνει επιπλέον τη GPU ελεύθερη αντί να
την κάνει να περιμένει αντιγραφή.

Αυτό αξίζει μόνο αν ο επεξεργαστής διαβάζει απευθείας τα συμπιεσμένα βάρη
4 bit. Εξ ου και ένας μικρός πυρήνας C++ με διαδρομή AVX2 (`acvram_cpu.cpp`,
φορτωμένος με ctypes, χωρίς κεφαλίδες Python ούτε ninja). Ακόμη και στον
**βαθμωτό** εφεδρικό κλάδο του, ξεπερνά το `dequantize() @ x` κατά 1,44 σε
INT4 και 3,21 σε NVFP4, επειδή το τελευταίο γράφει πρώτα ένα αντίγραφο 32 bit
ολόκληρου του πίνακα.

Στο Mistral-Large-123B, η εκτίμηση του σχεδιαστή περνά από 1,35 σε
2,42 tokens/s.

### Μικτή ακρίβεια (`--snr-floor`, απενεργοποιημένη εξ ορισμού)

Ο μετατροπέας μετρά τον λόγο σήματος/θορύβου στην έξοδο κάθε στρώματος για
κάθε τανυστή και μπορεί να προάγει σε ευρύτερη μορφή όσους πέφτουν κάτω από
`--snr-floor`, με όριο το 15 % των τανυστών και ένα ανώτατο κόστος
(`--promotion-cout-max`, σε προστιθέμενα mebibytes).

Το κατώφλι είναι **μηδέν εξ ορισμού**: τίποτα δεν προάγεται. Η
αποκωδικοποίηση περιορίζεται από το εύρος ζώνης μνήμης, και η μέτρηση στο
`Huihui-Qwen3.8-27B` κρίνει — κατώφλι 25 dB κοστίζει 13,4 % μνήμης και 10,6 %
απόδοσης (18,50 GiB και 41,8 t/s έναντι 16,02 και 46,2) για 2,0 % perplexity
(42,591 έναντι 43,447, σώμα κειμένων 16 383 tokens). Το `--snr-floor 25`
επαναφέρει την παλιά συμπεριφορά όταν η ποιότητα προέχει της ταχύτητας.

### Και `acvram eval`

Ο λόγος σήματος/θορύβου και το συνημίτονο των logits είναι προσεγγίσεις.
Το `acvram eval ΚΑΤ [ΚΑΤ ...]` μετρά την perplexity με κυλιόμενο παράθυρο,
ώστε μια επιλογή μορφής να κρίνεται με αποδείξεις:

```
$ acvram eval ~/acv/qwen3-32b-nvfp4 ~/acv/qwen3-32b-int4
  modele                   ppl     bpp      taille    jetons
  qwen3-32b-nvfp4        6,412    4,51    17,4 Gio      8192
  qwen3-32b-int4         6,583    4,17    16,1 Gio      8192  (+2,7 %)
```

πελάτες.

## Από πού προέρχονται οι αριθμοί

Κάθε τιμή που αναφέρεται παραπάνω παράγεται από κώδικα αυτού του αποθετηρίου
και ελέγχεται από το `pytest`. Μετρήσεις σε επεξεργαστή με τους πυρήνες
αναφοράς:

| μορφή | bit/βάρος | SNR βαρών | συνημίτονο logits έναντι BF16 |
|---|---|---|---|
| BF16 | 16,00 | — | 1,0000 |
| INT8 | 8,19 | 44,6 dB | 0,9998 |
| NVFP4 | 4,50 | 20,4 dB | 0,9664 |
| INT4 | 4,16 | 20,0 dB | 0,9427 |
| INT4 + Hadamard | 4,16 | 21,0 dB | 0,9582 |

Δύο διαπιστώσεις από αυτές τις μετρήσεις άλλαξαν τις προεπιλογές:

* **Μια περιστροφή Hadamard βοηθά το INT4 και όχι το NVFP4.** Οι ομάδες των
  128 του INT4 δεν μπορούν να απορροφήσουν ένα μεμονωμένο ακραίο κανάλι, οπότε
  η διασπορά των ακραίων τιμών αξίζει έναν μετασχηματισμό n log n ανά
  ενεργοποίηση. Τα μπλοκ των 16 του NVFP4 φέρουν ήδη τη δική τους κλίμακα. Εξ
  ου και `--hadamard auto`, που το εφαρμόζει μόνο στο INT4.
* **Το INT8 νικά το FP8 E4M3 για την κρυφή μνήμη KV**, 44 dB έναντι 32 dB σε
  ίδιο μέγεθος, επειδή μια κλίμακα ανά (token, κεφαλή) παρέχει ήδη το
  δυναμικό εύρος για το οποίο το FP8 ξοδεύει bits εκθέτη. Και οι δύο κάρτες
  χρησιμοποιούν λοιπόν κρυφή μνήμη KV σε INT8, αν και η 5090 θα μπορούσε FP8.

## Μετρημένα αποτελέσματα (22/09/2026, RTX 5090 στα 400 W, καθεστώς ≥ 20 s στον μετρητή ενέργειας)

Qwen3-Coder-30B-A3B σε NVFP4 (ειδικοί) + INT8 (προσοχή, κεφαλή), ίδιο
πρωτόκολλο για όλες τις μηχανές (`outils/`, μία κάρτα, `energie.py`):

| | acvram 0.6.35 | vLLM 0.29 (CUTLASS FP4) | llama.cpp (sm_120) |
|---|---|---|---|
| αποκωδικοποίηση 12 ακολουθιών | **1 625,5 t/s** | 1 596,1 t/s | — |
| αποκωδικοποίηση 1 ακολουθίας | **380,8 t/s** | 290,6 t/s | 323,6 t/s |
| prefill pp2048 | **22 707 tokens/s** | 21 054 | 8 671 (TabbyAPI, αποσύρθηκε) |

Απόδοση της ημέρας (σταθμός 1030, οικονομικό καθεστώς `-lgc 2700`, pipeline σε
λειτουργία· άπληστη δειγματοληψία αποτυπωμένη στον γράφο CUDA, ενεργή εξ
ορισμού στην 0.6.35). Το b=12 είναι το επίσημο σφραγισμένο κελί (διάμεσος 6
εναλλασσόμενων παραθύρων). Η τιμή vLLM 1 596,1 είναι η παγωμένη αναφορά της
21/09 (το vLLM δεν εκτελέστηκε ξανά εκείνη την ημέρα): η διαφορά +1,84 % ισχύει
με ίση αναφορά, όχι ως νέα μέτρηση και των δύο το ίδιο πρωί. Το J/token
μετριέται ακόμη ξανά (`outils/gpu/mesure/banc-4moteurs.py`) — αριθμός χωρίς
καθεστώς δεν δημοσιεύεται.

Το πρωί της 14/09 το acvram ήταν στα 630 t/s και 0,619 J/token στο ίδιο
κελί: τα κέρδη προέρχονται από το εγγενές FP4 MMA του Blackwell
(`mma.sync … kind::mxf4nvf4`, ×7,9 έναντι bf16), από το MoE ως ομαδοποιημένο
GEMM ανά κάδο παρτίδας, από δρομολόγηση σε έναν μόνο πυρήνα (3 677 → 1 517
εκκινήσεις ανά βήμα) και από ένα στενό GEMM σε tensor cores για τις
προβολές. Κάθε αριθμός έχει τη σημείωσή του στο `acvram-memoire/revue/` με
την πρόβλεψη σφραγισμένη πριν τη μέτρηση, το όργανο και το καθεστώς του —
αριθμός χωρίς καθεστώς δεν δημοσιεύεται.

Όπου το acvram προηγείται: μοντέλα MLA (GLM-4.7-Flash) σε εγγενές NVFP4
sm_120, που το vLLM σερβίρει μόνο σε FP8 (b=1: 165,35 t/s σε λειτουργία)· τα
μοντέλα που δεν χωρούν στη VRAM· και, από την 0.6.35, η αποκωδικοποίηση μεγάλης
παρτίδας ενός MoE που χωρά στη VRAM — το b=12 ανεβαίνει από 1 540 (0.6.34) σε
1 625,5 t/s, δηλαδή +1,84 % μπροστά από την παγωμένη αναφορά vLLM (1 596,1). Η
διαφορά παραμένει στενή και με παγωμένη αναφορά· η διαφορά ενέργειας πρέπει να
μετρηθεί ξανά.

## Κατάσταση

Έκδοση 0.6.35. Όλα τρέχουν στην 5090: πυρήνες CUDA μεταγλωττισμένοι για
`sm_120a` (εγγενές FP4) και `sm_86`, γράφοι CUDA, κβάντιση NVFP4/INT8/INT4,
διακομιστής HTTP. Προστατευτικά σε θέση: η κάρτα είναι αόρατη στις
συνεδρίες εργασίας (`CUDA_VISIBLE_DEVICES` κενό) και μόνο το
`outils/carte.sh` τη δανείζει, υπό κλείδωμα, σε μία μέτρηση τη φορά· ένας
φύλακας καταγράφει κάθε πρόσβαση εκτός κλειδώματος· μια μέτρηση ενέργειας
που καλύπτει πάνω από μία κάρτα ή κάτω από 10 s ακυρώνεται· ένα μοντέλο
φορτωμένο σε υποβαθμισμένο καθεστώς το δηλώνει και δεν μπαίνει σε μονομαχία.

640 δοκιμές (`pytest -q`, ένα λεπτό σε επεξεργαστή· οι δοκιμές GPU τρέχουν
μόνο υπό `carte.sh`). Παρακολούθηση εργασίας: `acvram-memoire/` (κανόνες,
