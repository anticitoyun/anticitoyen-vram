> תמיכה: [buymeacoffee.com/anticitoyen](https://buymeacoffee.com/anticitoyen)

שער הסקה תואם ל־API של OpenAI, המתייחס לזיכרון כאל היררכיה ונותן לכל GPU את
הפורמט המספרי שהסיליקון שלו קורא הכי טוב.

תוכנן למכונה אחת מסוימת:

| | |
|---|---|
| מעבד | Intel Core i9-14900K (8 ליבות P + 16 ליבות E) |
| לוח אם | ASUS ROG Maximus Z790 Dark Hero |
| זיכרון | 96 GB DDR5 |
| GPU 0 | ASUS RTX 5090 Astral LC OC, 32 GB — Blackwell, `sm_120` |
| GPU 1 | ASUS RTX 3080 Ti, 12 GB — Ampere, `sm_86` |
| מערכת | Ubuntu 26.04 LTS (CUDA 13); שני הכרטיסים ב־PCIe x8/x8, מוגבלים ל־400 W / 275 W |

## שני הרעיונות

**פורמט אחד לכל GPU.** ל־RTX 5090 יש ליבות טנזור FP4; ל־RTX 3080 Ti אין,
וגם לא FP8. יישור שניהם לפורמט משותף היה מבזבז את ה־5090. הממיר כותב לכן
*את אותו המודל פעמיים*, בפורמט שכל יעד באמת יודע לנצל:

| | RTX 5090 | RTX 3080 Ti |
|---|---|---|
| משקלים | **NVFP4** — E2M1 + סקאלת FP8 E4M3 כל 16 | **INT4** — uint4 + סקאלה ואפס fp16 כל 128 |
| ביטים למשקל | 4,50 | 4,16 |
| לעומת BF16 | קטן פי 3,56 | קטן פי 3,85 |
| מצב חישוב | ליבות טנזור FP4 | דה־קוונטיזציה ל־FP16 בתוך הקרנל, ליבות טנזור FP16 |
| מטמון KV | INT8 | INT8 |

32 GB של VRAM ב־4,5 ביטים למשקל מכילים כ־**56 מיליארד פרמטרים**, לעומת
16 מיליארד ב־BF16. על שני הכרטיסים זה בקירוב **78 מיליארד פרמטרים
תושבים** עוד לפני שנוגעים בזיכרון הראשי.

**הזיכרון הוא היררכיה, לא קיר.** שלוש שכבות, והמתכנן מודד כמה כל אחת עולה
במקום לקוות שהמודל ייכנס:

```
RTX 5090     32 Go   ~1790 Go/s     NVFP4
RTX 3080 Ti  12 Go    ~912 Go/s     INT4
DDR5 hôte    96 Go   limité par le PCIe ou la DDR
```

## התחלה מהירה

```bash
./install.sh                       # environnement virtuel + torch cu128 + acvram
acvram doctor                      # cette machine est-elle prête, et pour quoi
acvram detect                      # qu'y a-t-il réellement ici

acvram plan  ~/modeles/Qwen3-32B                    # où irait chaque couche
acvram convert ~/modeles/Qwen3-32B -o ~/acv/qwen3-32b
acvram serve ~/acv/qwen3-32b --port 8000
```

כל לקוח OpenAI מתחבר לאחר מכן:

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3-32b","messages":[{"role":"user","content":"Bonjour"}],"stream":true}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="inutilise")
client.chat.completions.create(model="qwen3-32b",
                               messages=[{"role": "user", "content": "Bonjour"}])
```

## מה אומר `acvram plan`

כדאי להריץ את המתכנן לפני כל הורדה. הוא עונה על השאלות שמכריעות אם מודל
שמיש במכונה הזו:

```
$ acvram plan ~/modeles/Llama-3.3-70B --max-model-len 32768 --max-seqs 4

  etage   format      capacite      poids         KV  tranche
  cuda:0  nvfp4        30,3 Gio   25,5 Gio   4,5 Gio  couches 0-58
  cuda:1  int4_awq     10,9 Gio    8,7 Gio   1,6 Gio  couches 59-79
  cpu     nvfp4        74,8 Gio    3,4 Gio       0 o  -

  poids au total     37,6 Gio
  lu par jeton       35,1 Gio
  KV par jeton       162,5 Kio  -> 39 843 jetons en cache
  MLP en RAM hote    55-58

  decodage estime    17,8 jetons/s  (lot de 1)
  prefill estime     847 jetons/s
```

הוא סורק את מרחב התצורות במקום להסתפק בראשונה שנכנסת, ושתיים מהחלטותיו
מנוגדות לאינטואיציה מספיק כדי להצדיק ניסוח:

* **הוא משאיר את ה־3080 Ti ללא שימוש** כשמודל נכנס ל־5090 לבדה. פרוסות
  של צינור רצות בטור: הוספת שלב של 912 GB/s לצינור של 1790 GB/s מאטה פענוח
  של זרם יחיד. כופים עם `--gpus all`.
* **הוא מכווץ את מטמון ה־KV כדי לשמור את המשקלים ב־VRAM.** כל ג'יגה־בייט
  שניתן למטמון הוא ג'יגה־בייט של משקלים שנדחק לאפיק ה־PCIe, וקריאת משקל דרך
  PCIe עולה בערך פי שלושים מאשר מ־VRAM. ב־70B שלמעלה, ההכרעה הזו לבדה מעבירה
  מ־2,3 ל־17,8 אסימונים/ש'.

## ללכת מהר

ארבעה שיפורים, כל אחד מאומת בהוכחת שקילות ולא רק בסטופר: שיפור שמשנה את
התשובה הוא באג.

### פענוח ספקולטיבי (`--speculative`)

פענוח אסימון אחד באצווה בגודל 1 מוגבל־זיכרון: המכונה קוראת את כל המשקלים
הפעילים כדי להפיק אסימון אחד. אימות K אסימונים מוצעים קורא את אותם משקלים
**פעם אחת בלבד**. שני מציעים:

* `ngram` (ברירת מחדל) — מחפש את הסיומת הנוכחית מוקדם יותר בהקשר ומציע את
  מה שבא אחריה. לא עולה דבר, לא דורש מודל. משתלם כשהפלט מעתיק את הקלט:
  עריכת קוד, RAG, תקציר.
* `draft` — מודל קטן על התקן שני. במערכת הזו ההתקן הוא ה־RTX 3080 Ti,
  שהמתכנן משאיר בכוונה בטלה לכל מודל שנכנס ל־5090.

הקבלה מדויקת, לא מקורבת: הצעה מתקבלת בהסתברות `min(1, p/q)` ודחייה דוגמת
מחדש מהחלק החיובי המנורמל של `p - q`. נמדד על 40 000 הגרלות מול טיוטה
מכוילת בכוונה גרוע, ההתפלגות הנפלטת נשארת בתוך 0,002 שונות כוללת מהיעד —
הספקולציה קונה מהירות, לעולם לא תשובה אחרת.

```
modele jouet, glouton, k=4    etapes   jetons/etape   sortie
  sans speculation                23           1,00   reference
  n-grammes                       13           1,77   identique
  brouillon (= cible)              5           4,60   identique
```

### מטמון תחיליות (פעיל כברירת מחדל)

בלוקים ממוענים לפי ה־hash *המשורשר* של פרוסת האסימונים שלהם: שתי בקשות
החולקות הנחיית מערכת חולקות את הבלוקים שלה, והשנייה כבר לא צריכה לחשבם
מראש. השרשור הכרחי: אותם שישה־עשר אסימונים בהקשר אחר לא מכילים את אותם
מפתחות וערכים, ו־hash של הפרוסה בלבד היה מגיש את המטמון של רצף אחד לאחר.

בלוק ששוחרר ותוכנו עדיין ניתן לזיהוי נכנס לתור LRU במקום לרשימת הבלוקים
הפנויים: כך המטמון שורד בין בקשות בלי לסרב אי פעם להקצאה שיכול היה לשרת.

### חישוב בשכבת המארח (`--host-exec`)

שכבה שמשקליה שוכנים ב־RAM יכולה להיות מועתקת ל־GPU או מחושבת במקום. שני
המסלולים מוגבלי־זיכרון וקוראים את אותם בייטים: המהיר יותר הוא זה עם האפיק
הרחב יותר — PCIe 5.0 x16 נותן כ־54 GB/s, DDR5 בשני ערוצים כ־70 GB/s —
וחישוב במקום גם משאיר את ה־GPU פנוי במקום להשאירו ממתין להעתקה.

זה משתלם רק אם המעבד קורא ישירות את המשקלים הארוזים ב־4 ביטים. מכאן קרנל
C++ קטן עם נתיב AVX2 (`acvram_cpu.cpp`, נטען דרך ctypes, בלי כותרות Python
ובלי ninja). אפילו בענף הגיבוי **הסקלרי** שלו הוא מנצח את `dequantize() @ x`
בפקטור 1,44 ב־INT4 ו־3,21 ב־NVFP4, כי האחרון כותב קודם עותק 32 ביט של כל
המטריצה.

ב־Mistral-Large-123B, הערכת המתכנן עולה מ־1,35 ל־2,42 אסימונים/ש'.

### דיוק מעורב (`--snr-floor`, כבוי כברירת מחדל)

הממיר מודד את יחס האות לרעש ביציאת כל שכבה לכל טנזור ויכול לקדם לפורמט רחב
יותר את אלה שיורדים מתחת ל־`--snr-floor`, עד 15 % מהטנזורים ועד תקרת מחיר
(`--promotion-cout-max`, במביבייטים נוספים).

הרצפה היא **אפס כברירת מחדל**: דבר אינו מקודם. הפענוח מוגבל ברוחב פס
הזיכרון, והמדידה על `Huihui-Qwen3.8-27B` מכריעה — רצפה של 25 dB עולה 13,4 %
זיכרון ו־10,6 % תפוקה (18,50 GiB ו־41,8 t/s לעומת 16,02 ו־46,2) תמורת 2,0 %
פרפלקסיטי (42,591 לעומת 43,447, קורפוס של 16 383 אסימונים). `--snr-floor 25`
משחזר את ההתנהגות הישנה כשהאיכות קודמת למהירות.

### ו־`acvram eval`

יחס האות לרעש והקוסינוס של הלוגיטים הם קירובים.
`acvram eval DIR [DIR ...]` מודד פרפלקסיטי בחלון נע, כדי שבחירת פורמט
תוכרע על ראיות:

```
$ acvram eval ~/acv/qwen3-32b-nvfp4 ~/acv/qwen3-32b-int4
  modele                   ppl     bpp      taille    jetons
  qwen3-32b-nvfp4        6,412    4,51    17,4 Gio      8192
  qwen3-32b-int4         6,583    4,17    16,1 Gio      8192  (+2,7 %)
```

## נקודות קצה HTTP

| נקודת קצה | הערות |
|---|---|
| `POST /v1/chat/completions` | זרם SSE או תשובה יחידה; משתמש בתבנית השיחה של המודל |
| `POST /v1/completions` | פרומפט כטקסט או כמזהי אסימונים |
| `POST /v1/embeddings` | ממוצע המצבים החבויים הסופיים, מנורמל L2, `dimensions` מכובד |
| `GET /v1/models` | בתוספת בלוק `acvram`: פורמטים, התקנים, קיבולת מטמון KV |
| `GET /health`, `GET /metrics` | תפוקת פענוח, תפוסת בלוקי KV |

שמות השדות בתשובות אלה נשארים באנגלית: זהו פרוטוקול OpenAI, ותרגומם היה
שובר כל לקוח קיים.

## מאין מגיעים המספרים

כל ערך שצוטט למעלה מופק מקוד במאגר זה ונבדק על ידי `pytest`. מדידות
שנעשו במעבד עם קרנלי הייחוס:

| פורמט | ביטים/משקל | SNR של המשקלים | קוסינוס לוגיטים מול BF16 |
|---|---|---|---|
| BF16 | 16,00 | — | 1,0000 |
| INT8 | 8,19 | 44,6 dB | 0,9998 |
| NVFP4 | 4,50 | 20,4 dB | 0,9664 |
| INT4 | 4,16 | 20,0 dB | 0,9427 |
| INT4 + Hadamard | 4,16 | 21,0 dB | 0,9582 |

שתי תובנות ממדידות אלה שינו את ברירות המחדל:

* **סיבוב Hadamard עוזר ל־INT4 ולא ל־NVFP4.** קבוצות ה־128 של INT4 לא
  יכולות לספוג ערוץ חריג בודד, ולכן פיזור הערכים הקיצוניים שווה התמרה n log n
  לכל אקטיבציה. בלוקי ה־16 של NVFP4 כבר נושאים סקאלה משלהם. מכאן
  `--hadamard auto`, שמחיל אותו על INT4 בלבד.
* **INT8 מנצח את FP8 E4M3 למטמון KV**, 44 dB לעומת 32 dB באותו גודל, כי
  סקאלה לכל (אסימון, ראש) כבר מספקת את הטווח הדינמי ש־FP8 מוציא עליו ביטי
  מעריך. שני הכרטיסים משתמשים לכן במטמון KV ב־INT8, אף שה־5090 יודעת FP8.

Qwen3-Coder-30B-A3B ב־NVFP4 (מומחים) + INT8 (קשב, ראש), אותו פרוטוקול לכל
המנועים (`outils/`, כרטיס אחד, `energie.py`):

| פענוח רצף אחד | **380,8 t/s** | 290,6 t/s | 323,6 t/s |
| prefill pp2048 | **22 707 אסימונים/ש'** | 21 054 | 8 671 (TabbyAPI, הוסר) |

תפוקות היום (עמדה 1030, משטר חיסכון `-lgc 2700`, צנרת בשירות; דגימה חמדנית
שנלכדה בגרף CUDA, ברירת המחדל של 0.6.35). b=12 הוא תא רשמי חתום (חציון של 6

(vLLM לא הורץ מחדש באותו יום): הפער +1,84% תקף בייחוס שווה, לא כמדידה מחדש של
שניהם באותו בוקר. מדד ה־J/אסימון בשעון זהה מול שלושת המנועים עדיין נמדד מחדש
(`outils/gpu/mesure/banc-4moteurs.py`) — מספר ללא משטר אינו מתפרסם.

בבוקר ה־14/09 acvram עמד על 630 t/s ו־0,619 J/אסימון באותו תא: הרווחים
מגיעים מ־MMA FP4 הילידי של Blackwell (`mma.sync … kind::mxf4nvf4`, פי 7,9
מול bf16), מ־MoE כ־GEMM מקובץ לפי דלי אצווה, מניתוב בקרנל יחיד (3 677 →
1 517 השקות לצעד) ומ־GEMM צר על ליבות טנזור להטלות. לכל מספר יש הערה
ב־`acvram-memoire/revue/` עם התחזית שנחתמה לפני המדידה, המכשיר והמשטר שלו —
מספר ללא משטר אינו מתפרסם.

היכן acvram מוביל: מודלי MLA (GLM-4.7-Flash) ב־NVFP4 ילידי sm_120, ש־vLLM מגיש
רק ב־FP8 (b=1: 165,35 t/s בשירות); מודלים שלא נכנסים ל־VRAM; ומאז 0.6.35, פענוח
באצווה גדולה של MoE שנכנס ל־VRAM — b=12 עולה מ־1 540 (0.6.34) ל־1 625,5 t/s,
כלומר +1,84% לפני הייחוס הקפוא של vLLM (1 596,1). הפער נותר צר ובייחוס קפוא;
הפער באנרגיה יימדד מחדש.

## מצב

גרסה 0.6.35. הכול רץ על ה־5090: קרנלי CUDA מהודרים ל־`sm_120a` (FP4 ילידי)
ול־`sm_86`, גרפי CUDA, קוונטיזציה NVFP4/INT8/INT4, שרת HTTP. מעקות בטיחות
במקומם: הכרטיס בלתי נראה למפגשי העבודה (`CUDA_VISIBLE_DEVICES` ריק) ורק
`outils/carte.sh` משאיל אותו, תחת נעילה, למדידה אחת בכל פעם; שומר רושם כל
גישה מחוץ לנעילה; מדידת אנרגיה המכסה יותר מכרטיס אחד או פחות מ־10 ש'
נפסלת; מודל שנטען במשטר מוחלש אומר זאת ואינו נכנס לדו־קרב.

640 בדיקות (`pytest -q`, דקה במעבד; בדיקות GPU רצות רק תחת `carte.sh`).
מעקב עבודה: `acvram-memoire/` (כללים, מדריך, מחברות, סקירה של 180 הערות).
